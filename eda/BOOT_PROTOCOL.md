# JTAG 程序装载和启动协议

芯片上电后先执行 boot RAM 的 `jal x0,0` 自环。下载器通过 JTAG halt CPU，向 `0x80000000` 开始的 8 KiB 主 SRAM 写入程序并完整回读校验，然后向 `0x00010000` 写入 `0x800002b7`，回读确认后用 `ndmreset` 重新启动 CPU。其余启动字保持 `0x00028293`、`0x00028067`，依次组成加载 SRAM 基址、ADDI、JALR 的跳转。

全局外部复位重新设置等待循环；`ndmreset` 保留主 SRAM 和 boot RAM 内容，用于执行已校验程序。`ndmreset` 同时复位 AXI 总线，所以不能在保持该复位有效时下载。下载失败时不得发布启动字或释放运行。

## 修改原因

原启动字会在上电后直接跳入未初始化 SRAM。门级被动追踪记录：720 ns 开始取 SRAM 指令，960 ns 返回未知指令，1000 ns CPU 控制变 X，1080 ns Debug 的 halted 状态变 X；随后未知写事务进一步污染可写 boot RAM。CPU 局部复位不重置 boot RAM，无法可靠恢复。初始外部复位边沿对照也复现了问题。

启动等待修复将 `rtl/memory/bootram.sv` 的上电第一条指令从 `0x800002b7` 改为 `0x0000006f`。另在 SoC 顶层修复以下复位释放时序。CPU 核、AXI/Debug 库和 NPU/DMA 运算实现不变。`rtl/manifest.json` 保留原文件 SHA-256，并通过 `project_override`、`integration_history` 记录集成修改和新哈希。

## 复位释放时序

保留原来的四级上升沿复位同步器，其输出接到新增下降沿寄存器的异步清零端；该寄存器输出才作为 CPU、互连、DMA 和 NPU 的 `ndmreset_n`。异步断言保留，释放发生在下降沿之后，给下游正沿触发器留出约半周期的 recovery/removal 预算。

此修改由真实 SDF 回标触发：原同步器在上升沿后释放复位，某些接收触发器的时钟到达为 120 ps、复位释放为 318 ps，两者只隔 198 ps，小于库要求的 285 ps removal。原启动等待版本共出现 445 条 removal 违规。新增寄存器由同步器输出清零，避免把原始外部复位恰在下降沿释放的问题引入新寄存器。20 ns 时钟下的理想半周期为 10 ns，实际验收仍以新网表的 SDF 和时序报告为准。

## 布线后验证采用的外部上电时序

本轮正式布线后 SDF 验证明确采用以下外部条件：

1. 从仿真开始保持外部复位有效，并将系统时钟保持低电平 1000 ns。
2. 1000 ns 后恢复原 20 ns 时钟发生器，第一个系统时钟上升沿为 **1010 ns**。
3. 外部复位仍按原流程等待八个下降沿后释放，时间为 **1160 ns**；其后的 JTAG 下载、完整回读和两次启动流程保持原有相对顺序。

[并行后仿入口](pnr/run_postroute_parallel.py) 的 `--poweron-settle-ns 1000` 只生成改变一个时钟发生器区域的派生测试台及差异记录，不修改原测试台、RTL 或固件，也不关闭任何 specify、timing check 或违规检测。时间等待是外部启动协议的一部分，没有通过强制内部节点初始化硬件。

这一条件来自实际布线后验收：原 MAX 基线虽完成软件两次启动，最初约 12 ns 仍出现一条 ICG E setup 和两条 SE setup 违规，因此严格结果为 FAIL。旧 MIN 完整场景的通过记录保留。新协议下 MAX/MIN 的 5000 ns 启动 smoke 无违规，但不能代替完整程序下载及两次运行；采用该协议的 MAX/MIN 四个完整场景均已实际 **PASS**，每场景两次启动、2048 字下载及回读，时序诊断为 0，详见 [物理实现记录](pnr/RESULTS.md)。

本协议不保证任意上电时序均可启动。如果产品要求系统时钟从上电起自由运行，需要另外提供复位和时钟门控初始化的设计保障，并在该条件下重新完成验证。

## 验证入口

`eda/sim/tb_soc_pins.sv` 通过顶层 JTAG 执行全部装载步骤，先回读 2048 个程序字，再校验三个启动字和发布后的首字，最后做两次独立复位运行。此流程可用于 RTL、门级和 SDF 仿真。

旧 `test/2026-10-15/rtl/tb_soc.sv` 仍是带内部存储端口预加载的功能测试：预加载完成后，在 CPU 复位同步器尚未释放时通过 boot RAM 端口写入原启动字。它只验证原有计算和协议回归，不作为真实硬件下载的证据。旧的未提交 JTAG 实验台尚未迁移，应使用新的 EDA 入口。
