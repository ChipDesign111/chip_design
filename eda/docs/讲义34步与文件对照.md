# 讲义34步：每步的动作、文件与效果

本篇是[操作指南](操作指南.md)的后端查阅附录。先按主指南完成部署、prepare、doctor和综合，再选择“分段运行”；不要先运行完整all后，再从01把本篇命令全部执行一次。

这里的命令都在服务器Bash运行，沿用主指南保存的`EDA_WORK`，当前目录为`EDA_DEPLOY`。所有相对文件路径以本轮`$EDA_WORK/`为根；`flow/`是prepare冻结的控制程序，`pnr/generated/`是根据实际几何生成的Tcl。步骤用到的源模板为`flow/tcl/steps/`下对应编号片段，实际执行正文保存在`evidence/commands/步骤号/`。这些Tcl由入口调用，不需要你另开工具手工source。

`--until N`表示从最后通过点连续运行到N。每步Tcl和自动审计通过后保存`evidence/step_NN.json`并推进`evidence/last_step.txt`；`.enc`加载脚本及`.enc.dat`数据库必须成套保留。部分阶段JSON只列少量自动检查，具体范围结合Tcl保护、日志和本步说明阅读。

最终报告路径、字段含义和异常分析方法见[报告查找与分析](报告查找与分析.md)。下文的“预期”不是本轮实测值。

## 01．导入新门级设计

**用到的文件：** `config/global_define.tcl、pnr/scripts/pnr_mmmc.tcl、syn/my_soc_top/my_soc_top_postsyn.v`。分别提供工艺路径、分析模型与综合后的单元连接；flow/tcl/driver.tcl负责导入。

**在干什么：** 读入新版SoC网表、库外形与时间模型，并查找唯一主SRAM。

**为什么要做：** 网表只写连接，库资料才给出实际器件；先排除旧网表、缺模型和选错宏。

**有什么效果：** 设计名my_soc_top，主SRAM恰好一个，记录综合后真实实例路径。

**关键参数：** 顶层固定为my_soc_top，宏型号固定RA1SHD_2048x32M8；实例名从当前数据库查询，不照搬旧层次路径。

```bash
bash server/bin/eda.sh pnr --work "$EDA_WORK" --until 1
```

成功后查看`evidence/step_01.json`与`pnr/my_soc_top/backup/step01.enc`；后者需要保留配套.enc.dat。

## 02．确定核心与裸片尺寸

**用到的文件：** `evidence/floorplan_plan.json、config/design.json → evidence/geometry.json`。前两者给出计划尺寸与边距；geometry.json记录工具网格吸附后的真实裸片坐标，后续外围据此生成。

**在干什么：** 根据新综合面积和目标放置密度估算核心，再由工具建立合法行网格。

**为什么要做：** 含PAD整颗面积受3.8 mm²约束，先用当前综合结果确认能否装入核心，再检查网格吸附后的真实外框。

**有什么效果：** 生成floorplan_plan.json与geometry.json，后续外围统一使用实际Die尺寸。

**关键参数：** 当前默认core_size_um=1648、target_utilization=0.85、外围边距150 um；若自动规划也必须满足含PAD整颗≤3.8 mm²。core7T提供合法行网格，实际Die尺寸用于后续坐标。

```bash
bash server/bin/eda.sh pnr --work "$EDA_WORK" --until 2
```

成功后查看`evidence/step_02.json`与`pnr/my_soc_top/backup/step02.enc`；后者需要保留配套.enc.dat。

## 08．连接PAD与核心

**用到的文件：** `pnr/my_soc_top/my_soc_top_io_connected.v、flow/tools/audit_io_topology.py`。网表记录改接后的内外两侧网络；审计程序比较原有内部端点，防止漏接。

**在干什么：** 先记录内部单元引脚，再把顶层端口转到外侧网络，从原引脚找到拆分后的内部网络，连接PAD/C/I及控制脚。

**为什么要做：** 输入应先经过接收电路，输出应经过发送电路；原内部端点必须一个不漏。

**关键参数：** 输入PAD：OEN=1关闭输出，IE=1开启输入，I/PE/DS=0。输出PAD：I接核心输出，OEN=0开启输出，IE/PE/DS=0。PAD是外侧端，C是接收输出，I是发送输入，不能混接。
