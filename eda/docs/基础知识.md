## 1. 电路怎样表示数字？

电路是电子器件和导电连接组成的系统。导线上的电压随时间变化，可以把信息传给另一个器件。**电压**是可以用电压表测出的两点之间的电气差异，单位是**伏特（V）**；本篇先把它理解为我们能测量的一种电气状态。测量需要一个共同的参考点，这个参考点通常叫**地**，不一定与物理大地相连。

用来表达或传递信息的电气状态及其变化，称为**信号**。后文说“信号到达”，就是有关电压变化已经传播到指定连接点。

数字电路把规定范围内的低电压解释为0，把规定范围内的高电压解释为1，常分别称为**低电平**和**高电平**。这样的一份0或1叫一个**二进制位**，英文是 **bit**。不是所有芯片都用同一个电压表示1；本实验核心采用1.8 V供电，实际允许的高低电平范围由所用电路规定。

一根信号线在一个时刻可表达一个二进制位。几根线合起来可以表达更大的数：

```text
四位二进制：0 1 0 1
各位的权值：8 4 2 1
表示的数值：0×8 + 1×4 + 0×2 + 1×1 = 5
```

这组信号有四位，叫**位宽为4**。四位可以表示0～15；两个这样的数相加，最大是30，需要五位才能完整保存。把多根相关信号作为一组使用，常称为**总线**，例如实验里的32位存储器数据总线。

现在知道了数字怎样表示。但导线只是传递状态，谁来完成加法？

## 2. 谁计算，谁保存结果？

### 2.1 计算依靠逻辑门

**逻辑门**是根据输入的0和1产生输出的基本电路。

| 门 | 输入与输出的关系 | 例子 |
| --- | --- | --- |
| 与门（AND） | 两个输入都是1，输出才为1 | 1与0得到0 |
| 或门（OR） | 至少一个输入是1，输出就为1 | 1或0得到1 |
| 非门（NOT，也叫反相器） | 把0变1、把1变0 | 输入1，输出0 |
| 异或门（XOR） | 两个输入不同，输出为1 | 1异或0得到1 |

用异或门、与门等连接起来，可以计算二进制加法。负责这种计算的电路叫**组合逻辑**：在电路稳定后，输出由当前输入决定，不靠它记住上一次的值。

逻辑门内部由**晶体管**构成。晶体管是可以受电信号控制导电状态的电子器件；把多只晶体管按一定方式连接，就能实现这些逻辑关系。学习本实验暂时不需要先画出每只晶体管的内部结构。

### 2.2 保存依靠触发器和寄存器

加法电路算出的5会随输入改变而改变。若希望“结果保存下来，直到下次更新”，还需要存储电路。

**触发器**是可以保存一个二进制位的电路。常见的一类触发器在指定时刻采样输入：输入端通常记作 **D**，保存后的输出通常记作 **Q**。把多只触发器一起使用，就能保存多位数，这组存储通常叫**寄存器**。五位寄存器通常需要五份一位存储。

决定何时采样的周期性信号叫**时钟**。电压从低变高叫**上升沿**，从高变低叫**下降沿**；两者都是**边沿**。本例假设寄存器在上升沿更新；两个相邻上升沿之间的时间叫**时钟周期**。

### 2.3 把小电路连起来

```text
外部数字a → [四位输入寄存器A] ─┐
                              ├→ [加法组合逻辑] → [五位结果寄存器Q]
外部数字b → [四位输入寄存器B] ─┘

时钟分别送到三个寄存器，决定它们什么时候保存输入。
```

假设周期20 ns。**ns是纳秒，即十亿分之一秒。** 在0 ns的上升沿，A和B分别保存2和3；接下来，加法电路的输出逐渐变为5。如果它足够快，20 ns的下一个上升沿就可以让Q保存5。

关键是：时钟决定寄存器**何时保存**，不让加法瞬间完成。信号穿过寄存器、逻辑门和导线都需要时间。后面检查“是否赶得上下一拍”，正是因为这些时间不能忽略。

也不是在同一个上升沿刚把2和3装进A/B，Q就立即保存这次算出的5。本例给计算留了一个周期，Q在下一个边沿保存这组输入对应的结果。

电路功能已经想清楚，接下来要把它交给设计工具。

## 3. 怎样把“我要这个功能”告诉工具？

我们可以写代码描述：“每次时钟上升沿，寄存器保存指定数据；两个输入寄存器的值相加，送到结果寄存器。”这种围绕寄存器及它们之间数据计算来描述电路的方式叫**寄存器传输级描述**，常缩写为 **RTL**。

RTL常用Verilog或SystemVerilog这类**硬件描述语言**书写。它们描述要形成的电路行为，不是让普通电脑按照代码顺序替芯片完成加法。本例的输入存储、加法电路和输出存储可以同时存在、持续工作。

RTL设计可以分成若干**模块**，即带接口的一块功能，例如加法器模块或存储器模块。最外层、代表整个当前设计的模块叫**顶层模块**。模块对外的输入或输出接口叫**端口**，英文 **port**。

本实验顶层叫 `my_soc_top`，包含处理器、存储和调试相关电路。**处理器**是按指令进行运算和控制的电路；**调试**是在运行中观察、控制有关状态，帮助定位问题。把这些功能集成在同一块芯片里的系统常叫 **SoC**，即“片上系统”。我们的小例子只是解释设计流程，不表示实验中的处理器仅有一个加法器。

RTL还没回答：选哪种具体逻辑门？每个门多大、放在哪里？这些问题需要实际可制造的电路资料。

## 4. 工具可以选择哪些真实电路？

### 4.1 制造方法和设计资料

芯片不能任意画几根线就制造。制造方规定材料、器件结构和允许的尺寸，例如金属线最小宽度、两条线至少相隔多少。这套制造方法和对应条件称为**工艺**。

制造方提供的设计资料集合叫**工艺设计套件**，英文缩写 **PDK**。Lab 4使用台积电180 nm工艺相关资料；**nm是纳米，即十亿分之一米**。“180 nm”是工艺名称的一部分，不表示所有图形都必须画成180 nm。

### 4.2 标准单元：可以反复使用的小电路模板

为了不用每次从晶体管重新画起，库设计者事先做好许多逻辑门、触发器等小电路。供工具选择的一组模板叫**标准单元库**，每个模板叫一个**标准单元**。

其中还有**缓冲器**：输出的逻辑值跟随输入，但可以帮助把信号传给较大的电气负担。它不等于零延时导线，本身也有传播时间。第9节会具体解释这种“负担”。

一种单元通常有三类资料：

| 我们需要知道什么？ | 对应资料 | 先怎样理解 |
| --- | --- | --- |
| 怎样运算、传递信号需要多久？ | **Liberty，通常是.lib文件** | 功能与速度说明书 |
| 多大、外部连接点在哪里、哪里不能走线？ | **LEF文件** | 安排位置和接线时使用的简化外形图 |
| 内部实际画了哪些制造图形？ | **GDS文件** | 包含内部真实几何的版图资料 |

**版图**就是按工艺层组织的几何图形，用来表达器件和导线如何制造。LEF省去了大量内部细节，只保留安排位置、接线等需要的信息，因此叫**物理抽象**。“抽象”不是虚构电路，而是有目的地省略细节。

工具不会每算一次延时就制造一个器件来测量，而是读取数据和规则来描述真实电路的行为。这种供计算使用的表示叫**模型**；模型的条件和精度会影响结果。

### 4.3 从RTL到选定的单元

把RTL变成具体单元及连接关系的过程叫**逻辑综合**。本实验的综合工具叫 **Genus**。

工具先理解模块关系，把代码结构展开成可处理的电路，称为**展开（elaboration）**；再调整逻辑表达，从库里选择具体单元实现功能，称为**映射（mapping）**。它还会在功能保持的前提下改善面积、耗电或速度，称为**优化**。

本例会从寄存器和加法的行为描述，变成指定型号的触发器、逻辑门及连接清单。这份清单叫**门级网表**；“门级”表示已经落实到逻辑门等单元层次。

工具还要知道目标。例如要求一个周期20 ns，就要在估计传播时间时考虑这份预算。描述时钟、接口时间要求等条件的文件叫**SDC约束文件**。第9节会完整解释如何判断时间满足要求。

综合后的网表仍未安排完整位置，也没有画出所有真实导线；它是后续物理实现的输入。

## 5. 怎样读懂网表里的“谁接谁”？

先区分“型号”和“用了一次这个型号”。设计中有100个同型号缓冲器，不代表有100种型号。

| 名称 | 含义 | 例子 |
| --- | --- | --- |
| 单元模板（cell/master） | 库中的电路型号 | 某一种缓冲器型号 |
| 实例（instance） | 在设计中使用一次该模板 | 缓冲器u_buf0 |
| 引脚（pin） | 实例的电气连接点 | u_buf0的输入I、输出Z |
| 网络（net） | 需要互相电气连接的一组引脚/端口 | 连接u_buf0/Z与若干输入脚的网络n_data |

**网络不等于已经画好的一根金属线。** 网表中属于同一网络，表示这些连接点应当连接；物理实现才决定用哪些金属线和跨层连接把它们真正接起来。

本实验的 `clk_i` 是整个设计接收时钟的端口。`i_pad_clk`是一个外围接口实例，`i_pad_clk/PAD`是该实例的外侧引脚。它们可能由一条也叫 `clk_i` 的网络连接，名字相似，但对象不同。

实例还可能位于其他实例里面，这叫**层次结构**。本分支RTL里的`i_mainmem/i_sram/i_macro`表示沿三层实例关系找到实际存储器，并不表示有三块物理存储器；综合后的实例路径仍要从当前数据库查询。

外围调试采用 **JTAG**，它是用少量信号与芯片交换调试/测试信息的一种串行接口。“串行”表示数据按先后次序传输。这里先记住各线的作用：

| 信号 | 作用 |
| --- | --- |
| tck_i | JTAG时钟 |
| tms_i | 控制JTAG当前操作状态 |
| td_i | 从外部串行送入数据 |
| td_o | 向外部串行送出数据 |
| rst_ni | 复位输入：本设计中为0时触发复位 |

**复位**是让指定存储状态回到设计规定的初始状态。本设计的 `_i/_o` 帮助表示输入/输出，`_n`帮助表示低电平有效；实际功能仍以电路定义为准。

有了连接清单，就可以安排真实空间了。

## 6. 电路放在哪里，怎样与芯片外面连接？

### 6.1 先划区域，再摆电路

**封装**是为芯片提供保护、机械支撑及对外电气连接的结构与工序。一块尚未装入这种结构的芯片裸片叫 **Die**；其中主要放内部计算电路的区域叫 **Core（核心区）**。外围还要留位置给外部接口等结构。

决定区域和大型电路位置，称为**布局规划（Floorplan）**。讲义原Lab4参考核心区约1500×1500 μm，四边边距150 μm；当前INT8工程请求1696×1696 μm，最终以本轮geometry为准。**μm是微米，即百万分之一米。** 按合法网格调整后，原Lab4参考Die为1800.4×1800.4 μm，不能当作本轮INT8的实测结果。

小型标准单元不是任意散放。它们沿一排排**单元行（row）**排列；放置位置使用的基本小格叫 **site**。当前库site宽0.56 μm，行高3.92 μm。把位置或尺寸调整到合法网格点，叫**吸附到网格（snap）**。

### 6.2 大存储器用已经做好的硬宏

大型存储器包含大量存储电路，逐个当普通逻辑门处理会很复杂。库提供内部已经设计好的大模块，称为**硬宏（hard macro）**，简称宏。其大小和内部引脚位置已确定，工具主要安排位置并连接外部接口。

本实验的宏是 **SRAM**，即一类在持续供电时可以保存数据的存储器，通常断电后内容丢失。型号 `RA1SHD_2048x32M8` 保存2048个32位数据，共65536 bit。8 bit为1字节，所以容量为8192字节，即8 KiB；1 KiB等于1024字节。

宏周围常要留一圈不放普通单元的空间，称为 **Halo（放置留白）**，帮助周边接线和合法放置。LEF还会标出某些层上已经被内部结构占用的区域，不能随意再走线，这些**布线阻挡**常标作 **OBS**。留白主要回答“哪里不放单元”，阻挡回答“哪里不能按通常方式画线”。

### 6.3 接口电路与金线接触区是两件事

负责输入/输出的外围电路叫 **IO**，即Input/Output。本实验把这些电路放在裸片边缘，所用外围单元称为 **IO PAD**。

输入IO单元接收外侧信号后送入内部；输出IO单元接收内部信号后向外发送。它们还含有库规定的接口/保护电路，具体能力取决于所用库，不能随意混接不同电压接口。

本实验的信号PAD型号为 `PDDW0204CDG`，同一种电路可用控制脚决定是否接收、是否向外发送。**使能（enable）**就是允许某项功能工作。例如OEN=0允许输出，OEN=1关闭输出；IE=1允许输入，IE=0关闭输入。这里不能凭“1就是开”猜测所有控制脚。

芯片后来要封装，本实验使用供金线接触的大金属区域，叫 **Bond PAD（键合焊盘）**。**键合**是把封装连接线与芯片焊盘连接的工艺。Bond PAD提供接触几何，IO PAD提供外围电路，两者需要正确对齐。

所以本实验34组IO/Bond几何覆盖可以是设计需要；两个普通逻辑单元占了同一块位置则通常是错误。判断覆盖前，先知道是哪两种对象。

区域和接口已经安排好了，电路还缺少最基本的条件：供电。

## 7. 有了逻辑连接，为什么还要专门设计电源？

### 7.1 电源和地

电路需要合适的供电电压，并允许电流经过电路返回参考端。常见名字 **VDD** 表示正供电网络，**VSS**表示供电参考/返回网络。

**电荷**是物质的一种电学性质；例如电子是带负电荷的微小粒子。电荷随这些粒子移动，形成**电流**。导线会阻碍电流，这种性质叫**电阻**。因此长或细的供电线，不能当成毫无影响的理想连接。

本实验核心用VDD/VSS，标称核心供电1.8 V；IO用VDDPST/VSSPST，对应标称3.3 V IO库的网络命名。四网保持独立，不可为了清除工具提示随意合并。库中的 **POC** 与IO上电控制相关，按讲义接指定IO供电；当前不用先拆解其内部电路。

**标称**指资料给出的参考工作值，不表示真实电压每时每刻都恰好等于该数。

### 7.2 “属于VDD”与“金属接到VDD”不同

网表把引脚归到VDD，只说明它应接电源。真实供电还需要金属结构。

在核心边缘做较宽的VDD/VSS金属圈，叫**电源环（ring）**；向内部铺条带，叫**电源条带（stripe）**；交叉连接后的分布结构常叫**电源网格**。标准单元每行还需要**行电源轨**，把供电送到该行的单元引脚。

```text
外部供电接口
    ↓
外围/核心电源环
    ↓
内部电源条带与网格 ───→ SRAM供电引脚
    ↓
各行电源轨
    ↓
每个标准单元的供电引脚
```

**PG**是Power/Ground的缩写，即电源与地。“PG连通检查”检查这些连接是否完整。`globalNetConnect`做网络归属绑定，`addRing`、`addStripe`、`sroute`创建有关金属连接；只做前者不等于完成后者。

### 7.3 供电和信号都需要多层金属

芯片有多层导线，通常从低到高记为 **M1、M2……**。层间导电连接叫**过孔（via）**；VIA12连接M1/M2，VIA45连接M4/M5。

平面图上看似交叉的两条线，可能在不同层；没有所需过孔，就没有在那里连接。反过来，本应独立的网络若在同层意外接触，可能短路。

本实验M4/M5承担核心电源环及主要网格，M1给标准单元行供电；SRAM附近用M5/M6补充高层接入。宏内一些低层已被占用，不能直接穿过去。

### 7.4 Tap、Decap、Tie和Filler分别解决什么？

除了计算电路，还需要为物理工作条件服务的单元。

**Tap（阱连接单元）：** 晶体管建立在硅里，作为器件基础的硅体称为**衬底**；工艺在其中形成的一类特定电学区域称为**阱**。这些区域也要通过导电路径接到工艺规定的参考电压，保持器件所需工作条件，不能只给逻辑信号脚接线。Tap提供相关连接，实验还检查其分布是否足够密。

**Decap（去耦电容单元）：** 电路切换时需要的电流会变化。**电容**是能储存电荷的电气结构，电压变化时会发生充放电。放在合适供电位置的电容可以帮助缓和短时电压波动。“去耦”在这里是减少通过共同电源产生的相互影响，不是切断电源，也不等于完成全部供电分析。

**Tie High/Low（常量驱动单元）：** 某些逻辑输入需要一直为1或0，库提供专门输出固定逻辑值的单元。它输出供逻辑输入使用的信号，不能拿来给整块IO电源网络供电。

**Filler（填充单元）：** 电路摆完后会有空隙，一些相关工艺/供电结构还需要连续。核心Filler填标准单元行空隙；IO Filler填外围IO之间空隙；**Corner（角单元）**让相邻两边的外围结构在转角处衔接。

这些单元任务不同，不能互相替代。它们解释了为什么完整版图里不只有计算逻辑。

固定结构和供电安排好后，工具才可以安置大量普通逻辑单元。

### 7.5 功耗报告里的数从哪里来？

接上电源以后，电路会消耗电能。**功耗**是每秒消耗多少能量，单位是瓦特（W）。数字电路即使没有计算，也可能有少量**漏电**：器件在理想情况下应该关断，实际仍有微小电流。

另一部分消耗来自信号变化。导线和器件输入具有电容；电压从低变高时，需要从电源取得能量为它充电。信号经常变化，通常比长期保持不变消耗更多能量。这叫**开关功耗**的一部分。驱动更多寄存器的时钟网络也有这类负载，因此插入时钟缓冲器不只影响时间和面积。

减少不需要的时钟切换，是降低这类消耗的一种方法。**时钟门控**是根据控制条件暂停给部分电路送时钟；控制“本次是否更新”的信号常叫**使能信号**。库里的**ICG（集成时钟门控单元）**把门控及保持控制稳定所需的电路做在一起，避免控制变化产生不希望出现的短脉冲；这种短脉冲常叫**毛刺**。当前流程的Genus模板允许自动推导这种单元，不能仅凭某个RTL时钟包装模块是直通，就判断整个综合网表没有门控。

要估算这部分功耗，工具需要知道信号多久变化一次。这些变化情况叫**开关活动**。20 ns周期只说明时钟多久来一次，并不说明每条数据线每拍都会变化。

可以把功能仿真的信号变化记录成**VCD**文件，或把变化次数等统计写入**SAIF**文件，再交给功耗分析工具。它们描述的是所模拟输入下的活动；输入不具有代表性，估计也会偏离真正的使用情况。

如果没有提供这些活动数据，工具可以根据默认概率推算，常称为**无向量估算（vectorless）**。当前INT8 SoC的Genus功耗报告使用这种估算；时钟树运行日志还记录了未提供默认输入活动时采用0.2的工具默认值。这个值是分析假设，不能解释为真实NPU任务的测量结果。报告有功耗数字，也不能直接据此宣布某次推理消耗多少能量。

## 8. 普通逻辑单元怎样摆才算好？

把单元安排到实际坐标，叫**放置（placement）**。它不仅要放得下，还要考虑连接距离和后续接线空间。

本例的加法器离输入寄存器很远，导线会更长，传播时间可能增加；所有门挤在一处，也可能没有足够空间接线。某区域预计需要的线太多、可用通道太少，称为**布线拥塞（congestion）**。

工具还检查**放置合法性**：单元是否在允许的行/区域内、是否越界、是否发生禁止的覆盖。**unplaced**表示实例尚未放置；最终不能遗留需要放置却没有位置的逻辑单元。

**放置密度**反映单元占用面积相对报告所定义可用面积的比例。是否计入宏、固定单元、Filler，会影响口径。插完Filler后“含Filler密度”100%，不表示逻辑计算单元把所有布线空间挤满了。

现在位置更真实，但完整信号线还没画好。工具先估计连接，再根据正式布线更新。接下来回到第2节的问题：数据能赶上下一个时钟边沿吗？

## 9. 结果何时到达，何时必须稳定？

### 9.1 导线和负载为什么也影响时间？

实际导线带有电阻，导线与周围结构、接收电路还带有电容。改变网络电压，需要给这些电容充放电，所以信号不会瞬间从低变高或从高变低。

导线及连接带来的电阻、电容常合称 **RC**：R代表电阻，C代表电容。真实连接本身也有这些性质，不需要额外画一只独立器件才出现，因此常称**寄生电阻/电容**。“寄生”指伴随结构出现，不是多了一种逻辑功能。

负责送出信号的输出电路叫**驱动端（driver）**；接收端及有关连线形成**负载（load）**。负载更重，往往更难快速改变电压。一个输出直接连多少个接收输入，叫**扇出（fanout）**；相同扇出也可能电容不同，因为各输入大小不同。

现在可以解释本实验PAD的另外两个控制脚。**DS选择输出驱动能力**，即电路向连线及接收端充放电的能力；DS=0为低驱动，DS=1为高驱动。**PE控制下拉电阻**：通过较弱的电阻连接，把外部无人主动发送时的接口倾向于拉到低电平，减少状态不确定的问题；PE=1启用、PE=0关闭。前者关系到带动负载的能力，后者关系到无主动发送者时的默认状态，作用不同。

电压完成一段规定范围变化所需的时间叫**转换时间（transition）**，时序语境中也常叫**slew**。它描述边沿有多快；**传播延时（delay）**描述输入变化后相关输出变化晚到了多久，两者不是同一个数字。

### 9.2 先用数字理解Setup

送出数据的寄存器叫**发射寄存器（launch）**，准备保存数据的寄存器叫**捕获寄存器（capture）**。本例A/B是发射端，Q是捕获端。

触发器不能在一个没有宽度的数学瞬间完美采样。为可靠保存，输入需要在捕获边沿之前稳定一小段时间，叫**建立时间（setup time）**；相应检查叫 **Setup检查**。

以下只是教学数字，假设两端时钟同时到达，周期20 ns：

```text
0 ns：发射端收到上升沿
2 ns：新数据到达发射寄存器Q输出
17 ns：经过组合逻辑与导线，结果到达捕获寄存器D
20 ns：捕获端收到下一次上升沿

若捕获端要求提前1 ns稳定：
最晚允许到达 = 20 − 1 = 19 ns
实际到达     = 17 ns
剩余时间     = 19 − 17 = 2 ns
```

这2 ns叫**时序裕量（slack）**。正值表示还有时间，负值表示迟到了。若实际21 ns才到，而最晚应在19 ns到，slack就是−2 ns，Setup失败。

### 9.3 为什么太快也可能有问题：Hold

捕获端还要求输入在本次采样边沿之后继续保持一小段时间，叫**保持时间（hold time）**，相应检查叫 **Hold检查**。

它关心：本次要保存的值，是否在保存过程还没结束时，就被发射端下一份新值过早替换？因此Hold不是“下一周期有没有算完”的另一种说法。

```text
教学例子：
捕获端本次边沿到达：0 ns
输入需要保持到：   0.2 ns
发射端新值最早到D：0.1 ns

新值来得过早，保持裕量 = 0.1 − 0.2 = −0.1 ns → Hold失败
```

Setup希望慢路径别太慢；Hold希望快路径别过快。修Hold常加入合适的延时单元或缓冲器，让新数据晚一点到，但不能把Setup原本的预算用完。这就是“修Hold时保护Setup”的原因。

### 9.4 WNS、TNS和DRV怎么读？

**静态时序分析（STA）**根据连接、单元延时、连线延时和时间要求，计算有关路径是否满足条件。它不依赖你恰好仿真到一次2+3的输入，而是按约束及模型做路径时间分析。

| 字段 | 含义 | 例子 |
| --- | --- | --- |
| WNS | 最差时序裕量；本实验工具摘要也显示正值 | 最差−0.03 ns表示仍有失败项 |
| TNS | 按该报告口径累加的负时序裕量 | 两个被计数项−0.03和−0.01，总和−0.04 ns |
| Violating Paths | 被报告为违规的路径/检查数量 | 数量1不能说全部通过 |
| DRV | 电容、转换时间、扇出等电气限制违规 | 输出负载电容超过库规定上限 |

先抓住“最差值、负值总和、违规数量”三个意思。显示 `-0.000` 可能只是小数位不够，违规数非0就不能宣布清零。

**Real/Total DRV**是工具对电气违规的分类统计，Real0不等于Total0。要看报告给其他项加了什么分类标记，例如本次preCTS有6个电容项计入Total，均标为时钟网络相关的C类，需要时钟树完成后复查，而不是自行忽略。电气DRV也不同于后面讲的几何DRC。

时间要求懂了，但前面假设时钟同时到达各处。真实芯片能完全同时吗？

## 10. 怎样把同一个时钟送到几千个寄存器？

### 10.1 时钟也要导线和驱动

一个时钟源若直接拖着几千个输入和很长导线，负载很大，边沿和延时难控制。工具在途中布置缓冲器逐级分发，形成类似树枝的网络，叫**时钟树**。

构建它叫**时钟树综合（CTS）**。本实验用Innovus里的 **CCOpt** 命令完成相关时钟网络及时序协调优化；它是工具功能的名称，不是一种额外物理单元。

末端接收时钟的引脚常叫 **sink（接收点）**，不是新器件类型。从源到接收点的传播时间叫**时钟插入延时**，也会看到 **latency** 这个词。

### 10.2 时钟偏斜为什么影响Setup和Hold？

假设时钟到发射端是0 ns，到捕获端是0.5 ns。两端到达时间不同，叫**时钟偏斜（skew）**。定义skew为“捕获端到达−发射端到达”，此例为+0.5 ns。

捕获端下一拍也相应晚到，数据有更多时间完成计算，通常帮助Setup；但本次采样也变晚，新数据有可能在保存旧数据的过程中过早到达，通常恶化Hold。具体仍须结合实际路径和边沿分析。

这解释了实验顺序：放置后先做时钟树，再分别重查Setup和Hold，不能只看Setup变好。

### 10.3 理想、传播和虚拟时钟

树没做好时，分析采用简化的时钟假设，称为**理想时钟**；做好后，将实际网络传播影响用于分析，称为**传播时钟（propagated clock）**。

本实验 `sys_clk`来自真实输入，周期20 ns；`jtag_clk`来自JTAG时钟输入，周期100 ns，两路都建物理树。

`virtual_jtag_tck`周期1000 ns，是描述外部接口时间关系的**虚拟时钟**：一个分析参考，没有对应芯片内真实源线，所以不建物理树、不设传播时钟。它与真实JTAG时钟不是同一对象。

### 10.4 外部模型和预留时间

工具还要知道外部时钟边沿多快。本实验假设输入transition=0.5 ns，给源设置5 pF允许电容负载。**pF是皮法，电容单位，等于万亿分之一法拉。** 5 pF是源模型允许的负载，不是额外加一只5 pF电容。

实际时钟可能有波动，模型也有不确定性。因此时间分析预留一份预算，叫**时钟不确定度（clock uncertainty）**。它是要求，不是物理插入的延时。本实验物理时钟Setup/Hold分别预留0.47/0.2 ns。

SDC里的**输入延时（input delay）**描述外部数据相对参考时钟何时到达芯片接口；**输出延时（output delay）**表达外部接收方对输出时间的要求。它们不同于输入边沿transition。

有些路径按工作方式不需要通常的同周期检查，通过**时序例外（exception）**表达。例如**假路径（false path）**表示指定路径不参与相应检查，不表示真实错误已经修好，不能为清零违规随意添加。

位置和时钟更真实后，还要把剩余信号真正接起来。

## 11. 怎样从连接清单走到实际金属？

决定各网络用什么层、什么位置的导线与过孔连接，叫**布线（routing）**。本实验物理实现工具叫 **Innovus**，前面的规划、放置、供电和时钟树也在它里面完成。

先粗略规划连接经过的区域，叫**全局布线（global routing）**；再确定满足几何规则的具体线和过孔，叫**详细布线（detail routing）**。早期用于估计的**试布线（trial route）**不是最终布线。

正式线画好后，工具按实际几何重新计算导线电阻、电容，称为**寄生参数提取（RC extraction）**。所以正式布线后要重查时序，之前估计的线长和负载可能不准确。

只改少量单元或线路时，可做局部更新，常称为**ECO（工程变更）**。**增量修复**是基于已有设计只处理有关部分。但改一处线可能影响附近间距、改变延时，不能省检查。

本实验是：正式布线→查天线并局部修复→真实RC检查Setup/Hold→必要时全设计自动修Hold→插核心Filler→最终复查。天线的含义在下一节马上解释。

“全设计自动修Hold”是让工具搜索整个设计需要调整的路径，不是照历史端点名单逐个手改。20 ps目标希望留一点正裕量；**ps是皮秒，1000 ps=1 ns，所以20 ps=0.02 ns。** 这不表示更改SDC里的原始要求。

线都接完，为什么还要这么多种检查？

## 12. 怎样证明“这一步做对了”？

每种检查只回答它负责的问题，不能用“工具没报Error”代替全部验收。

### 12.1 功能：算得对吗？

**仿真**是在电脑里用模型模拟电路，给定输入并观察输出。例如输入2和3，检查应更新时Q是否为5。有限输入仿真通过，不自动证明所有可能情况；仿真中加法正确，也不说明版图VDD已接通。

### 12.2 时序：来得及，而且没过早改变吗？

用第9节Setup/Hold等检查判断。本次最终教学模型下，最差Setup/Hold裕量0.641/0.019 ns，违规数0。它说明在所用约束与模型下满足这些检查，不代表验证了所有制造和工作条件。

### 12.3 连通：该接的接了吗，不该接的分开了吗？

**开路（open）**是应连在一起的部分缺少完整导电连接；**短路（short）**是本应独立的网络意外连接。**未连接端子**是需要连接的引脚没有接到所需导线。

**悬线（dangling wire）**通常是一端没有继续使用的线段；**孤立金属（floating metal）**是没有按要求连接的独立金属部分。悬线不自动等于整行断电，但要看位置、内部连接和完整报告，不能看到该词就忽略。

### 12.4 几何：画法符合工艺规则吗？

制造对线宽、间距、过孔覆盖等有要求。两条不同网络的线虽未接触，间距过小也可能违规。检查这些规则叫 **DRC（设计规则检查）**。

命令中 `special`主要指电源等特殊布线，`regular`指常规布线；最终几何检查用讲义的 `default` 范围。前期只查电源金属通过，不代表后来信号金属也通过。

### 12.5 实际几何表达的是原来的电路吗？

从版图识别器件和连接，与目标网表比较，叫 **LVS（版图与电路原理比较）**。它与“线距够不够”的DRC不同。

实验导出 `flat_lvs.v` 为后续比较提供源网表，没有运行独立工艺LVS。文件名包含LVS不等于已经检查；RC提取里的内部“Checking LVS”信息也不能替代独立工艺LVS验收。

### 12.6 制造时会不会损伤器件：工艺天线

晶体管里有很薄的**绝缘层**：这种材料不会让电流像经过金属导线那样自由通过。在某些制造阶段，较大金属可能收集电荷，使与它连接的薄绝缘结构两侧出现过大的电压并损伤它。这叫**工艺天线效应**，不是无线电发射天线。

工具按金属面积、所连器件有关面积等规则检查风险。修复可改变走线层次/形状，必要时加入库允许的**天线二极管**，即用于相关电荷泄放的器件。之后还要重查几何、连通和时序。

### 12.7 IO的两项no routing为什么保留？

回想第4节：LEF是简化资料，GDS含真实内部几何。本库部分IO侧轨没有完整呈现为LEF里可用于工具外部连通分析的布线，所以有两项 `no routing`，即“该检查没有找到对应布线”。

本次结合**原生GDS**（库原本提供的真实几何）、四边PAD/Filler连续的位置和方向、四角连接，核对了这些轨的几何拼接，并按讲义保留抽象限制推进。

这是针对具体网络和对象的判断，不是说所有no routing都可忽略，也不等于全芯片独立LVS已通过。重跑有其他开路/短路，要重新定位。

这些本阶段检查结束后，还要把同一个最终设计交给后续软件。

## 13. 最后为什么要导出这么多文件？

同一个电路需要不同视角：功能、连接、位置、制造几何、时间要求和传播时间。后续软件的任务不同，需要的信息也不同。

| 阶段 | 文件 | 记录什么 |
| --- | --- | --- |
| 设计输入 | RTL，.v/.sv | 寄存器更新与组合计算行为 |
| 设计输入 | Liberty，.lib | 可选单元的功能、延时、电气限制 |
| 设计输入 | 库LEF | 尺寸、引脚、阻挡的简化资料 |
| 设计输入 | 库GDS | 单元内部真实制造几何 |
| 输入/最终保存 | SDC | 时钟、接口时间要求及例外 |
| 综合输出 | 门级网表，.v | 使用哪些单元，怎样连接 |
| 物理输出 | DEF | 当前实例位置、顶层端口和布线 |
| 物理输出 | SPEF | 提取出的网络电阻、电容 |
| 物理输出 | SDF | 当前条件下的单元/互连延时及有关时间检查 |
| 物理输出 | 顶层LEF | 将当前整体作为大模块供后续集成使用的简化外形 |
| 物理输出 | 合并GDS | 当前设计与库单元真实几何组合后的版图 |
| 中途/最终保存 | .enc及.enc.dat | Innovus恢复数据库，也叫检查点 |

**SPEF**用于交换寄生参数，**SDF**用于交换延时资料。把SDF读入门级仿真模型，模拟这些延时的影响，叫**延时回标仿真**。只写SDF、检查实例名匹配，不等于实际运行了它。

本实验有两类最终网表：**平坦网表（flat）**把有关实例展开到同一层次，供指定后续比较流程使用；**层次网表（hierarchical）**保留模块层次，方便与SDF路径对应。两者排除对象不同，不能随意互换。

**纯物理单元**主要提供工艺/几何作用，没有要参加普通逻辑计算的功能，例如某些Filler和Bond单元。它们可从特定逻辑用途的网表中排除，但真实GDS仍要保留几何。

合并GDS要同时放入标准单元、SRAM、IO和Bond的原生GDS。GDS里的**结构**可以看成命名的几何模板；另一结构使用它，叫**结构引用**。引用不存在的结构，相当于图纸要求放一个零件，却没有这个零件的图形。

文件完整性、端口坐标、网表/SDF名字、结构引用和单位核对，检查这些视角是否一致，但不能代替其他类别的验收。

这条主线现在完整了：**综合确定用哪些电路；物理实现确定放哪、怎么接；检查确认在规定范围内满足要求；交付保留后续软件需要的不同表达。**

## 延伸A：单次时序通过为什么不等于最终签核？

这部分用于理解报告范围，第一次阅读可先完成正文。

器件速度会受制造差异、供电电压和温度影响。三类条件合称 **PVT**，即工艺Process、电压Voltage、温度Temperature。

一组规定的分析条件常叫**角（corner）**。**TT**常表示典型工艺组合；**FF/SS**等表示其他工艺速度组合，不是软件运行速度，也不是仅凭名字就能确定所有最坏情况。

**模式（mode）**描述按哪套工作方式和约束检查，例如普通功能或测试工作。支持多模式、多条件组合分析的组织框架叫 **MMMC（多模式多角）**。有该框架，不表示本次已经检查很多角。

| 工具对象 | 已知信息如何组合 |
| --- | --- |
| constraint mode，约束模式 | 使用哪份SDC和工作要求 |
| library set，库集合 | 选择哪些单元时间/电气模型 |
| RC corner，连线RC条件 | 怎样给导线计算电阻、电容 |
| delay corner，延时条件组合 | 将单元模型与连线RC条件组合 |
| analysis view，分析视图 | 再加入约束模式，形成可分析的一套组合 |

本实验活动视图 `func_tt_io` 只用选定TT条件，仍是单TT教学分析。核心库和IO库在同一视图里可有各自规定的供电模型，不能从视图名或SDF头部推断所有单元电压相同。

邻近导线可能通过电容等作用互相影响，改变边沿或延时，叫**串扰**；考虑这类信号影响的分析常称 **SI（信号完整性分析）**。本次SI关闭，不表示真实芯片没有物理耦合。

`postRoute low RC`表示当前原生、低精度等级的布线后RC提取设置。**CapTable**是RC计算数据表的一类；**Quantus**是Cadence寄生参数提取工具名称，更完整流程可能需要其对应工艺技术文件，本实验没有使用Quantus签核技术文件。

两个可能遇到的词：

- **OCV，片上变化模型：** 同一芯片、同一标称条件下，器件/连接速度仍可能不同，工具按规定模型在时间分析中考虑差异。
- **CPPR，公共路径悲观量去除：** 两个时钟分支可能共用一段实际线。若把同一段同时按互相不一致的最慢/最快情况计算，会多出保守量；CPPR处理其中重复悲观部分，不是删除真实时间要求。

这里的“保守/悲观”是指估计偏向对设计更不利的条件，预留更多余量；不是描述工程师的情绪。

最终项目还可能要求：

| 项目 | 解决的问题 |
| --- | --- |
| IR drop，供电压降 | 电流经过有电阻的供电网后，负载处电压下降多少 |
| EM，电迁移 | 电流长期流过时，是否使金属原子逐渐迁移，形成薄弱处甚至断线 |
| ESD，静电放电 | 短时静电脉冲是否损伤接口或内部电路 |
| 独立工艺DRC/LVS | 按指定工艺规则/提取流程检查最终实际版图 |

按项目规定完成必要验证，决定能否交付制造，通常叫**签核（signoff）**。本次完成Lab 4的综合、物理实现和导出核对，没有宣称完成上述所有签核。

## 延伸B：读命令前，先知道你在操作哪里

| 名称 | 含义 |
| --- | --- |
| 服务器 | 安装设计工具、运行实验的远端电脑 |
| SSH | 从本机连接远端命令终端的方法 |
| SCP | 本机与远端之间传文件的方法 |
| shell | 接收并执行系统命令的程序，例如Linux里的bash |
| PowerShell | 本机Windows使用的一种命令环境 |
| Tcl | Innovus等工具使用的命令语言 |
| Makefile | 把启动、切换目录等命令组织为命名任务的文件 |
| 脚本 | 保存了一组命令的文件，执行效果取决于内容 |

分清三层：Windows里SSH/SCP；登录服务器后处理文件、启动工具；Innovus提示符下用Tcl操作设计。不能把dbGet粘进普通Linux shell，也不能把scp当设计命令。

**工作目录**是解释相对路径的基准；`.`表示当前目录，`..`表示上一级；`pwd`查看工作目录。按报告启动后，Innovus位于新工程的pnr/logs：

```text
新工程/
├── evidence/
└── pnr/
    ├── logs/         ← 当前工作目录
    └── my_soc_top/   ← ../my_soc_top

logs回两级是工程根，../../evidence指上面的evidence。
```

**变量**是用名字保存一份值的方式。例如`set x 5`把5存为x，Tcl里的`$x`读取这个值；`[命令]`先执行内层命令，再使用结果；花括号常把一组文字原样传入。所以含[2]的网络名常写`{sram_wdata[2]}`，避免误当内层命令。

`dbGet`查询设计数据库。**数据库对象**可以是实例、引脚、网络或几何；**对象指针**是工具引用对象的标识，不是一根电气线。`-p/-p2`返回有关层次的对象引用，`0x0`通常表示没找到。

`source`在相应命令环境里读取并执行文件。实验允许原Makefile初始化，但后续要逐步操作，不整体source实现阶段脚本。`saveDesign`保存恢复点；名字叫timingFixed不自动证明时序通过。

## 用六个问题检查是否理解

1. 网表说两个引脚属于同一网络，是否已经有真实金属连接？
2. 输入都是2和3，为什么仍要关心加法用了多少时间？
3. 为什么Hold失败时有时要让信号变慢？
4. 为什么做完时钟树要重新查Setup和Hold？
5. 为什么DRC0不能代替LVS或供电连通检查？
6. 为什么要用多种文件表达同一个设计？

对应答案：

1. 还没有。网表给出应当连接的关系，真实金属由物理布线完成。
2. 结果正确还不够。它必须在寄存器要求的采样时间窗口内保持稳定，才能可靠保存。
3. Hold限制新数据最早何时可以到达；适当增加延时，可以避免旧值尚未采样完就被替换。
4. 时钟树改变了时钟到两端的实际时间，Setup和Hold各自可用的时间因此改变。
5. DRC查几何规则，LVS查几何表达的电路是否匹配，供电连通检查查导电路径；一种检查通过不能回答另外两种问题。
6. 逻辑连接、实际位置、制造图形和延时是不同信息，后续任务需要不同的表达。
