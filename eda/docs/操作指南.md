# W8A4 SoC：可以逐步照做的EDA操作指南

这份指南实施当前分支的完整my_soc_top，按Lab 4的G1–G4、01–34执行。目标包含CPU、AXI、Debug、Boot、主SRAM、NPU和DMA，不能只跑NPU的Yosys检查就结束。

正文把Windows PowerShell、服务器Linux shell、工具内部Tcl分开。你只需在前两种终端运行下面的入口，复杂Tcl由脚本执行。想理解电路概念先读[基础知识](基础知识.md)，具体适配见[实施说明](实施与适配说明.md)。

**0．先认识三个路径。** 仓库保存源码和可提交的EDA程序；部署目录保存上传解压后的server/与rtl/；工作目录保存一次真实实验的配置、报告和检查点。它们不应是同一个目录。服务器工作目录名使用英文字母、数字、下划线或短横线，避免空格和Tcl特殊字符。PDK和授权SRAM留服务器，不放Git仓库。

**P1．本机核对分支并生成部署包。** 以下在Windows PowerShell运行，在xzx/rtl的仓库根目录。已有本机主目录有其他未提交代码时，不要强制切换它；使用当前独立的xzx/rtl工作目录。

```powershell
git branch --show-current
python tools/project.py check
python -m unittest discover -s eda/tests -v
python eda/package_server.py
```

在干什么：先检查目录政策、保留外围源码SHA与新自动化，再把server/和同版本rtl/打包。有什么效果：生成eda/dist/chip_design_eda.tar.gz及.sha256。包中的功能基线来自仓库既有PASS记录，脚本核对RTL SHA；它不表示刚刚重新仿真。功能变更时应先完成当前单元/双后端SoC回归再打包。

**P2．上传服务器所需文件。** 仍在Windows PowerShell：

```powershell
scp -o ClearAllForwardings=yes .\eda\dist\chip_design_eda.tar.gz .\eda\dist\chip_design_eda.tar.gz.sha256 chipdesign:~/
ssh -o ClearAllForwardings=yes chipdesign
```

在干什么：只上传部署专用包并登录服务器。ClearAllForwardings避免原SSH配置的本地端口转发冲突；不改你的SSH配置。部署包不含PDK、厂商模型、数据集和历史数据库。

**P3．解压到新部署目录，设置本轮工作目录。** 从这里起在服务器Linux shell执行：

```bash
cd "$HOME"
sha256sum -c chip_design_eda.tar.gz.sha256
export EDA_DEPLOY="$HOME/chip_eda_deploy_$(date +%Y%m%d_%H%M%S)"
mkdir "$EDA_DEPLOY"
tar -xzf "$HOME/chip_design_eda.tar.gz" -C "$EDA_DEPLOY"
cd "$EDA_DEPLOY"
export EDA_WORK="$HOME/chip_eda_runs/w8a4_$(date +%Y%m%d_%H%M%S)"
printf '%s\n' "$EDA_DEPLOY" > "$HOME/chip_eda_latest_deploy.txt"
printf '%s\n' "$EDA_WORK" > "$HOME/chip_eda_latest_work.txt"
```

在干什么：用SHA核对传输，再分开部署与运行位置。时间戳可避免覆盖旧结果；实际操作时不要同时开两套会写同一工作目录的流程。目录变量必须保留；重新登录时可用后文恢复命令读取。

**P4．检查并选择参数。** 默认使用server/config/design.json：20 ns系统周期、8 CPU、0.5目标放置密度、根据新面积自动估算核心，最小核心1500 um、外围150 um；主宏坐标(250,650)，最多3次修复。库路径默认/home/almalinux/tsmc180，宏源默认/lec/lab4/soc_cv32e40p_template_pnr-stu/src/macro/RA1SHD_2048x32M8。

先阅读配置，再决定是否用默认值：

```bash
cat server/config/design.json
cat server/config/io_plan.json
```

如需改参数，在准备前复制配置并编辑，不要改已经开始运行的工程输入：

```bash
cp server/config/design.json "$HOME/w8a4_design.json"
# 使用你熟悉的编辑器修改 $HOME/w8a4_design.json
# 下个prepare命令末尾增加 --config "$HOME/w8a4_design.json"
```

配置字段与限制见server/README.md。首轮保留现有CPU时钟直通及权重bank实现，不同时改功能、门控和流水。原28个供电PAD方案是教学起点，不是已通过供电压降/电迁移分析的结论。

**P5．准备一份新工程。** 默认配置这样执行：

```bash
bash server/bin/eda.sh prepare --work "$EDA_WORK"
```

在干什么：复制同源RTL快照和本地授权宏，生成带SYNTHESIS/CHIP_USE_RA1SHD的77源文件清单，修正路径，创建输出目录，保存输入SHA。有什么效果：src/config/syn/pnr/flow/evidence结构完整，原Lab 4和仓库功能源码都不被覆盖。目录已存在就停止，避免误覆盖。

**P6．检查库和环境，暂不启动商业EDA。**

```bash
bash server/bin/eda.sh doctor --work "$EDA_WORK"
```

在干什么：检查Genus/Innovus可执行文件，用tclsh展开配置，检查并记录实际Liberty、LEF、GDS、RC表和层映射的SHA。有什么效果：生成evidence/doctor.json。物理入口只需Python 3.8+标准库；仓库功能测试另需Python3.11+和相应仿真器，二者不要混为一谈。默认环境脚本由eda.sh加载；登录Shell的系统Python可能为3.6，加载课程环境后本服务器选用3.8.10，因此使用eda.sh入口，或用EDA_PYTHON显式指定3.8+解释器。若tclsh或Xvfb缺失，先联系环境维护方或用已有安装。

**G1．先展开RTL，尽早检查语法和模型。**

```bash
bash server/bin/eda.sh elaborate --work "$EDA_WORK"
```

在干什么：Genus读取库、77份源码，建立模块关系并检查设计；还没有完成工艺映射和面积优化。有什么效果：evidence/genus_elaborate.log、elaborate_check.rpt与elaboration_status.json。看到缺模块、错误位宽、非法语法或非预期悬空信号，要先定位；命令完成不等于功能正确。

**G2–G4．执行完整SoC综合并验收交接输入。**

```bash
bash server/bin/eda.sh synth --work "$EDA_WORK"
bash server/bin/eda.sh size --work "$EDA_WORK"
```

在干什么：综合将RTL映射为TSMC180具体逻辑单元及一个主SRAM宏；随后读取真实Cell Area估算核心。有什么效果：syn/my_soc_top下的postsyn网表和报告，以及evidence/synthesis.json、synthesis_status.json、floorplan_plan.json。

自动检查主SRAM唯一、映射后叶单元都有库模型、无非预期Latch面积、NPU/DMA面积层次仍在。它仍不能代替功能等价验证。size会分开标准单元、宏/留白空间，不使用Net Area当单元面积；这只是规划起点，最终看拥塞、时序和供电。

**接下来怎样运行后端。** 推荐先分段观察：

```bash
# 01–14：导入、外围、宏与端口
bash server/bin/eda.sh pnr --work "$EDA_WORK" --until 14
# 15–23：电源网格及辅助物理单元
bash server/bin/eda.sh pnr --work "$EDA_WORK" --until 23
# 24–26：普通逻辑放置、Tie及preCTS检查
bash server/bin/eda.sh pnr --work "$EDA_WORK" --until 26
# 27–29：时钟树与树后时间检查
bash server/bin/eda.sh pnr --work "$EDA_WORK" --until 29
# 30–34：正式布线、修复、最终复核和导出
bash server/bin/eda.sh pnr --work "$EDA_WORK" --until 34
```

每次入口启动新Innovus进程，恢复最后一个完成自动检查的步骤；步骤不是可任意跳过的菜单。--until 14表示从当前进度连续运行到14，并不表示只执行14。若想真正逐步观察，把--until依次设为1、2、3……34即可。已完成的目标会拒绝重复执行。

默认使用当前DISPLAY；没有时自动申请一个空闲Xvfb，仅回收本次启动的显示。--headless可关闭图形模式并跳过截图，检查范围不因此自动放宽。原始运行记录在evidence/innovus_起止步骤.log及pnr/logs，按当前几何生成的Tcl在pnr/generated/；实际执行过的片段另存evidence/commands/步骤号/，宏路径已替换为数据库中的真实实例，自动报告会逐段附上这些命令。

下面按讲义解释每一步。表述中的“预期”是应该达到的效果，当前运行是否完成要看该工程evidence/step_XX.json、日志和检查点，不能照抄本文当结果。

## 01．导入新门级设计

**在干什么：** 读入新版SoC网表、库外形与时间模型，并查找唯一主SRAM。

**为什么要做：** 网表只写连接，库资料才给出实际器件；先排除旧网表、缺模型和选错宏。

**有什么效果：** 设计名my_soc_top，主SRAM恰好一个，记录综合后真实实例路径。

**关键参数：** 顶层固定为my_soc_top，宏型号固定RA1SHD_2048x32M8；实例名从当前数据库查询，不照搬旧层次路径。

```bash
bash server/bin/eda.sh pnr --work "$EDA_WORK" --until 1
```

成功后查看`evidence/step_01.json`与`pnr/my_soc_top/backup/step01.enc`；后者需要保留配套.enc.dat。

## 02．确定核心与裸片尺寸

**在干什么：** 根据新综合面积和目标放置密度估算核心，再由工具建立合法行网格。

**为什么要做：** NPU权重和乘法逻辑增加面积，不能直接复用原1500尺寸；网格吸附后坐标也会变化。

**关键参数：** core_size_um为空时根据新Cell Area自动估算；target_utilization默认0.5，外围边距150 um，core7T提供合法行网格。工具实际Die尺寸用于所有后续坐标。


## 08．连接PAD与核心

**在干什么：** 先记录内部单元引脚，再把顶层端口转到外侧网络，从原引脚找到拆分后的内部网络，连接PAD/C/I及控制脚。

```bash

```

status给出当前配置、综合状态和最后完成步骤；report生成evidence/运行报告.md，未完成步骤明确标注。日志里找EDA_STAGE_FAILED、EDA STOP及第一条实际Error。每步开始前清除本步应重新生成的旧报告，避免失败时误读上次输出；通过的报告另存evidence/stage_reports/步骤号/并记录SHA，防止后续同名报告覆盖历史证据。对未放置、缺库、非预期开短路、时序残项，按对应报告修复原因。不要仅靠“工具进程正常退出”判断成功。IMPSP-9099仅在步骤24且该轮独立放置检查已通过时分类保留，记录在classified_placement_messages.json；其他阶段或缺少检查证据时仍中止。

检查点在每步命令结束后保存，自动检查通过才推进last_step。`.enc`是工具生成的加载脚本，`.enc.dat`是配套数据库目录；恢复入口读取加载脚本，两者必须一起保留。失败后新入口恢复上一个通过点，不在失败后被部分修改的数据库上重复addInst。中断后如遇flow.lock，先用ps核实进程；只在拥有进程和记录的工具子进程都已经退出时运行unlock。入口会在正常中断时清理自己启动的工具进程组；unlock不会杀死进程，也不清除其他主机的锁。

