# 从已完成版图继续做完整SoC后仿

后仿使用版后网表和SDF。网表描述实际单元与连接；SDF给出单元、导线延时和时序检查限值。调用sdf_annotate不等于正确完成回标：还必须检查实例、检查项是否匹配，以及实际延时是否生效。

## 1．本机启动

先确认已保存的EDA版本完成34步，且硬件源码对应这份版图。默认从本机eda/dist/last_upload.json选择已完成的物理版本。以下命令创建新的上传目录，不重跑综合或布局布线，不修改原work。

```powershell
python eda/postsim.py run
python eda/postsim.py status
```

指定其他已完成物理版本时：

```powershell
python eda/postsim.py run --eda-upload /home/s2400011041/Desktop/fullstack_chipdesign/uploads/20261027_132429_5b60015
```

run先生成固件镜像，再调用正式打包器上传、校验并解压到新uploads/版本目录。后台运行原生Innovus与所选仿真器，版本位置记录在本机eda/dist/last_postsim.json。大网表、SDF、授权模型、可执行程序和编译数据库留服务器。本命令只验证选定的物理实现，不代表当前分支的新约束已经完成实现。

单独修改后仿平台时，可以继续使用同一物理数据库；修改RTL、SDC、库角或物理配置时，必须先新上传完成物理实现。当前四库角修复版导出TT与跨角SDF，依次串行验证：

```powershell
python eda/postsim.py run --simulator vcs --sdf-mode tt
# 此次完成并回传后，再启动下一次；不能同时运行多个重任务。
python eda/postsim.py run --simulator vcs --sdf-mode pvt-min
python eda/postsim.py run --simulator vcs --sdf-mode pvt-max
```

tt读取TT专用SDF并选MAXIMUM；pvt-min/pvt-max读取同一跨角SDF，分别选择MINIMUM快角、MAXIMUM慢角。每次均新目录，名称带工具及SDF模式。选定历史后仿版本用status/fetch的--upload完整路径，避免last_postsim切换后读错结果。

每次包含16组正常SDF和1组独立无SDF功能对照，共17组。故意PAD冲突及额外初始化诊断已退出生产矩阵。原生输入PAD的时间0初始化消息原样保留、分类，不要求恰好出现5条或全部Warning为零；后续真实冲突、缺失回标、功能错误和动态时序违规仍须处理。

外部驱动在2ns接通。时钟先保持低电平40ns，让原生模型在复位有效期间完成初始传播；第一个上升沿在50ns，此后仍为20ns周期。原先第一个上升沿在10ns时，新实现的10条告警全部落在11.398～11.831ns的初始传播阶段。延后起振没有修改SDF、关闭检查或改变工作频率，正式矩阵仍保留全部阶段的时序检查及16个最终复位相位。

可用--simulator xcelium作独立交叉诊断。当前模型实测存在SDF边沿路径不匹配和部分负延时补偿失败，不能仅凭功能PASS将它当作完整验收替代。audit.json分别给出绑定完整性和负延时支持完整性；大型原始回标日志留服务器，回传保留编译摘要与警告分类。

对已完成物理数据库作只读多库角分析：先python eda/pvt.py run，再status和fetch --output空目录。它匹配库额定电压/温度、保留原始路径和聚合TNS，并复核输入SHA不变；读取同一数据库不做ECO。这类测量发现负余量后，应新上传重新实现，不能编辑旧work来拼接。

## 2．服务器每一步在干什么

| 步骤/文件 | 做什么 | 为什么及效果 |
| --- | --- | --- |
| configs/firmware*.hex | CPU自检程序、输入、权重、逐值黄金结果 | 12组训练双样本和4组随机双样本，既测原例也扩大功能覆盖 |
| deploy/server/postsim/run.py | 总控并记录输入SHA、实际命令、退出码 | 每次新建postsim目录，避免混入旧可执行程序 |
| export_view.tcl | 只读加载原step34数据库，重新导出含实际天线二极管的仿真网表 | 原教学紧凑网表省略二极管，会丢失对应SDF互连端点；这里没有ECO |
| inputs/timing.sdf | 解压原最终SDF，不改原时序数值 | 保持与原静态时序/版图的可追溯关系 |
| inputs/sram_period_adapter.v | 授权模型的服务器私有副本，只补齐负边沿period声明 | 原SDF有该检查，原模型只有正边沿声明；复用原NOT_CLK_PER，不放宽限值，限值由SDF填入 |
| build/compile.log、sdf.log | VCS编译与回标 | VCS会在编译期预处理常量sdf_annotate文件，SDF必须预先放在编译目录 |
| sdf_max/simulation.log | 20ns系统周期、MAXIMUM SDF、完整时序检查 | 全程启用消息和notifier；保留初始、工作、最终复位事件 |
| build_zero、gate_zero | 独立编译的无SDF、零延时门级功能对照 | 仅该对照使用NO_SDF、notimingcheck与delay_mode_zero；同时去掉原生模型自带延时，避免理想互连和模型延时混合造成竞争。全部SDF组保留真实延时、检查和notifier |
| sdf_firmware_*/ | 相同SDF可执行程序运行其他镜像 | 每组独立加载完整SRAM、提交启动、执行CPU/NPU/DMA自检 |
| collect.py、audit.json | 分析回标和动态事件，形成回传包 | 不以功能PASS掩盖错误；区分工作窗口与复位阶段，保留全部消息 |

NTC和RECREM是原标准单元模型支持的宏分支，不是新写的逻辑模型。配合VCS的neg_tchk/negdelay选项，支持原模型内负的setuphold、recovery/removal检查。不能把模型中的负时序值默认置零后宣称所有检查正确。

本测试通过Debug SBA请求边界加载固件，实际经过AXI和SRAM接口，不直接写SRAM数组，也不强制CPU结果。CPU默认禁止取指，检查部分加载、错误密钥、完整覆盖、复位余量；固件逐值比较隐藏层、六个分数和分类，还检查tile数和MAC发射数。通过后读取SRAM统计，确认DMA读写确有MAC重叠。

SRAM复位接口修正后，必须先对新RTL完成独立的34步EDA，再对该版数据库运行本脚本。SRAM在系统上升沿接收寄存命令，在随后的系统下降沿执行；需要确认STA分析了这两段真实半周期路径。完成标志从宏的实际写入观察。首组保持最终复位偏移2ns，其余15组从0.25ns到19.85ns均匀覆盖一个系统周期；日志RESET_ASSERT和results.json记录实际相位。复位后还检查宏CEN恢复为禁止访问。所有SDF时序检查及notifier始终开启，分类初始/工作/最终事件不等于屏蔽。

## 4．如何判读

先看audit.json的annotation_errors、missing_instances、unmatched_timing_checks，再看每组functional_pass和timing_counts。CLOCK_AT_CORE记录真实PAD后时钟边沿，便于与无SDF对照核对延时确实生效。

active窗口从稳定复位后的加载前开始，到功能/统计检查完成、最终复位前结束。窗口只用于分类，未关闭任何SDF消息或notifier。工作窗口为0条不代表复位阶段没有事件；初始和最终复位事件必须另列。notifier是库模型在违规时产生X的机制，不能全程关闭后冒充时序通过。

某些VCS警告明确表示仍会回标，例如Simple Wire Connection；另一些表示负IOPATH被截零或特殊顶层端口互连处理。这些限制必须按类别、数量和对象列出，不把零error扩展成所有延时毫无损失或完整签核。

面积和静态WNS来自已完成的物理数据库；动态后仿没有改变面积，也不能用动态无违例代替多PVT静态签核。现有功耗报告若没有相同活动输入，不应直接当作本轮后仿功耗。独立DRC/LVS、IR/EM和形式等价也不由本流程自动完成。
