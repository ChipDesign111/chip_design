# 按上传版本隔离的服务器结构

顶层为 `~/Desktop/fullstack_chipdesign`。每上传一次就在uploads下新建目录，压缩包放在该目录。**公共解压器只有顶层unpack.sh；解压后的脚本、配置、操作和结果全部属于对应上传目录。**

```text
fullstack_chipdesign/
├── unpack.sh                         公共解压入口
├── README.html / README.md            版本索引，无全局运行状态
├── uploads/
│   ├── 20261022_时间_提交A/
│   │   ├── chip_design_eda.tar.gz     本次原包
│   │   ├── chip_design_eda.tar.gz.sha256
│   │   ├── upload.json               包SHA、提交及解压记录
│   │   ├── deploy/                   本版本server、rtl、docs、source.json
│   │   ├── configs/design.json        本版本准备前参数
│   │   ├── work/                     本版本唯一实现工程、数据库及所有输出
│   │   ├── logs/                     本版本入口日志
│   │   ├── results/summary.json       本版本状态与最终结果摘要
│   │   ├── docs/                     本版本说明
│   │   ├── run_env.sh                只指向本目录
│   │   ├── run_all.sh                本版本完整流程
│   │   ├── collect_results.sh        本版本结果收集
│   │   └── README.html / README.md   本版本GUI与文本说明
│   └── 20261022_时间_提交B/           完全独立，不引用A的配置、脚本或work
├── lab4/                             原Lab4内容完整保留
└── history/                          历史有效结果，不作为新上传输入
```

首次把仓库eda/unpack.sh放到服务器顶层。每次新建上传目录后，把本次部署包及.sha256放入其中，再执行：

```bash
cd "$HOME/Desktop/fullstack_chipdesign"
bash ./unpack.sh uploads/这里替换为本次目录
```

公共解压器检查原包SHA、归档路径与逐文件SHA，再解压到该版本deploy。相同原包重复调用可恢复说明入口，但不覆盖已有work或用户配置；同一版本目录换成不同原包时拒绝覆盖。解压后不自动启动EDA。

进入对应版本目录运行：

```bash
cd "$HOME/Desktop/fullstack_chipdesign/uploads/这里替换为本次目录"
source ./run_env.sh
bash ./run_all.sh
```

所有路径由本目录的run_env.sh确定。首次从RTL开始，完成综合、01–34、报告和结果打包；同版本重复调用仅在自己的work内续跑。需要新源码或新流程时重新上传到另一个目录，不能修改其他版本的配置或借用其检查点。

双击顶层README.html选择版本，再双击版本内README.html查看目录和结果。版本脚本只刷新本版本说明，不改顶层“当前版本”指针，因为不存在这种指针。状态缺失不表示通过，最终以本版本work/evidence/step_33.json、step_34.json及原报告为准。

单独重新生成结果用本版本collect_results.sh。清理用本版本deploy/server/bin/eda.sh clean --work "$PWD/work" --dry-run预览，去掉--dry-run执行；只清理交付包与已知暂存，保留原包、清单、报告、日志、中间文件、检查点及最终视图。

Lab4原始内容和历史有效结果保留在顶层对应目录。旧记录含原绝对路径，保留其原样；新版本不使用旧工程作为输入。详细上传、分段实施、分析和回传命令见[操作指南](操作指南.md)。
