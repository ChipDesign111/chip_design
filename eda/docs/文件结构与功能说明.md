**正式运行模块的作用：**

| 文件 | 为什么需要 |
| --- | --- |
| `server/tools/generate.py` | 按实际裸片宽高、IO计划及宏坐标生成本轮Tcl |
| `server/tools/checks.py` | 读取实际面积、时间和物理报告，决定阶段是否达到验收要求；报告缺失不能按0违规处理 |
| `server/tools/audit_io_topology.py` | 检查插PAD改接后没有丢失原内部端点，四个电源网络独立 |
| `server/tools/audit_io_ties.py` | 核对PAD控制脚的常量及供电端未被Tie错误替换 |
| `server/tools/gds_audit.py` | 读取最终GDS结构、引用、单位及选定端口几何；不是独立LVS工具 |
| `server/tools/audit_native_io_rails.py` | 核对当前IO库原生供电长轨和角部，与实际外围连续布局共同判定两项库抽象限制 |
| `server/tools/light_delivery.py` | 生成轻量回传包；大型物理和寄生文件留远端并登记路径、大小和SHA |
| `server/tools/cleanup.py` | clean预览/删除明确列出的打包产物；也供打包流程清理暂存文件，不删除实现中间文件 |
| `server/tools/workspace.py` | 在本次uploads/版本目录生成README.html、run_env.sh、完整运行入口和结果摘要；不创建共享状态 |

这些模块是时序/DRC/连接验收与结果收集的一部分，会在正常EDA过程中执行。开发自检、测试数据、兼容性试验、跨工程检查点导入工具和原始参考模板不在分支内。

**部署后如何变为本轮工程：** prepare直接复制正式 `config/` 中的Tcl和 `syn/`、`pnr/` 脚本到新工作目录，写入本轮工程路径、PDK路径、周期和CPU数；不读取参考模板。源码复制到 `src/chip_design/rtl/`，完整授权宏复制到 `src/macro/`。控制程序快照在 `flow/`，后续调用使用该快照，同一工程不会随部署目录更新而改变。

| 本轮工作目录文件 | 作用与使用时机 |
| --- | --- |
| `config/design.json` | prepare时固定的本轮参数，不再随部署配置变化 |
| `config/user_define.tcl` | 本轮绝对路径、周期和CPU数，global_define通过PDK_ROOT定位工艺 |
| `src/filelist_syn.f` | 77份源码的绝对路径及SYNTHESIS/CHIP_USE_RA1SHD开关 |
| `evidence/input_manifest.json` | 固定输入身份，保护同一工程的检查点恢复 |
| `evidence/doctor.json` | 实际使用库的路径与SHA，避免续跑混用变化后的库 |
| `evidence/floorplan_plan.json` | 真实综合面积驱动的核心规划 |
| `evidence/geometry.json` | 工具网格对齐后的裸片及派生端口坐标 |
| `evidence/step_NN.json` | 每步实际验收结果与原报告引用 |
| `evidence/commands/NN/` | 该步实际执行的Tcl，不是示例命令 |
| `evidence/stage_reports/NN/` | 被引用原报告的阶段副本，防止同名输出覆盖历史 |
| `evidence/运行报告.md` | 逐步解释、实际命令及本轮结果 |
| `pnr/my_soc_top/backup/` | 正常断点续跑数据库；enc与enc.dat成套保留 |
| `pnr/my_soc_top/outputs/manual_final/` | DEF、网表、时间/寄生和GDS等最终交付 |

`results/` 保存历史实测与原报告，不作为新工程的输入。正常复现从当前RTL开始；自己的新结果放对应上传目录内的work，按指南轻量回传到本地lab4，大型数据库和库文件不提交Git。

下载校验后可运行`eda.sh clean --work <目录> --dry-run`预览，再去掉`--dry-run`清理本轮交付压缩包及已知暂存文件。清单、报告、日志、中间文件、数据库和最终导出保留；清理不需要重跑EDA，也不会更新输入清单。
