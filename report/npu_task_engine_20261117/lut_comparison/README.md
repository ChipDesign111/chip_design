# 查表访问比较：功能周期已测，面积待测

直接访问：每个INT8索引读取主SRAM中对齐的32位字，经现有DMA写入32位查表落地寄存器，再选一个字节。

候选缓存：复用上述32位寄存器作为一行4B缓存，仅增加11位物理SRAM字地址标签和有效位及命中控制。表仍占主SRAM的256B；不增加256B寄存器阵列。LUT_WORD_CACHE参数为0时不支持缓存、CAP bit6=0，新增标签逻辑应在综合中消除；为1且描述符LUT_CACHE=1才使用。START/ACK/旧模式启动/复位/错误撤销缓存，成功的非缓存LUT访问也撤销旧标签，避免落地字被覆盖后误命中。

全SoC实际CPU运行、同一量化参考，且两种程序机器码SHA一致（任务表的缓存位不同）：

| 模型输入 | 直接访问周期 | 候选缓存周期 | LUT主SRAM读取字节，前→后 |
| --- | ---: | ---: | ---: |
| Sigmoid，4×32有序输入 | 1657 | 1209 | 512→256 |
| Tanh，4×32随机输入 | 1657 | 1636 | 512→500 |
| FC→Sigmoid→Tanh，两张表 | 2165 | 2132 | 512→488 |
| 原混合网络 | 2548 | 2521 | 48→36 |

这是4B行缓存的实际局部性结果；不能把有序输入27%的收益套到随机网络。每个命中省去一次完整DMA控制/AXI读写响应，仍保留逐个后处理和整数边界。包含输入、输出、CPU轮询等整程序开销，没有把DMA两端字节相加成SRAM读取量。

模块级另覆盖全部256种INT8索引、相同地址在新执行段换表内容、两张表与直接访问交错、读写失败和六个阶段系统复位，验证缓存有效性撤销。候选与直接方案都通过旧模式切换和忙时启动拒绝测试。

[实测结果及源码SHA](result.json)。目录保存每个模型的启动镜像、参考/实际输出、任务表、逐值边界trace、周期/流量JSON及无损压缩的逐拍CSV。

两轮Genus均完成，候选缓存的整设计净面积差为+0.000487335mm²，决定保留这一字缓存；数据存储仍复用原32位落地寄存器。硬件默认参数改为1，任务可选直接读。整体任务引擎首轮面积超预算，必须先完成 [面积收紧](../area/README.md)，再验收布局和时序；不能把缓存的很小增量等同于整个新硬件的增量。
