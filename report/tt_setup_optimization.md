# TT负路径与慢角Setup优化

本轮从2026-10-29按用户延后5小时的要求启动。优先让TT负IOPATH截零消息由18降至0，并增大SS125 Setup余量；同时观察FF−40的438条截零是否减少。基线4427c4b已通过正常教学EDA/SDF，不覆盖或篡改它的原始结果。ASIC基线来自main d40b217，后续只提交xzx。远端main另有FPGA更新至99aa863，ASIC RTL树保持一致；本轮未修改或合并main。

## 已定位的基线问题

TT原始SDF中有18条负IOPATH弧，涉及16个组合单元。INVD1有5条、INR2D1有8条、AOI21D0有1条、MUX2ND0有3条、NR2D1有1条；同一MUX的无条件及两个条件弧分别计数。最负约−0.030ns。原始库表也包含负值，因此不能靠把SDF数值改成0、删除弧或关闭检查宣称解决。

同数据库原生路径报告显示，例如CPU CSR通路的g36996由约1.227ns边沿驱动，输出负载约0.003pF，其单元延时约−0.022ns。缓慢输入、轻输出负载时，输出跨过计时阈值可能早于输入跨过阈值；这属于原生时序模型，不能直接解释为逻辑功能错误。其余实例、原始弧及数值见[基线清单](../eda/results/tt_setup_optimization_20261029/baseline.json)。

慢角最差路径由CPU ID阶段alu_operand_b_ex_o_reg[16]经过ALU加法链回到mult_operand_c_ex_o_reg[27]，Setup为+0.001ns。此前最差Hold为FF−40的+0.020ns，不能只修Setup而忽略快角Hold。

## 这一轮改什么、为什么

1. `combinational_cell_mapping=tt_nonnegative_tables`：从服务器未修改的原生TT Liberty读取组合单元cell_rise/cell_fall表，暂不选用含负表项的组合单元；使用同一库中其他单元重新实现原布尔逻辑。该选择在Genus初始化前后及Innovus创建/恢复后统一应用，记录原生库SHA和实际应用。它改变实际网表及版图，不改原生模型或SDF。实际工作点可能发生插值/外推，所以表筛选不等于已证明最终SDF负弧为0，必须重新实测。
2. `implementation_effort=high`：提高综合及摆放时序优化力度，为完整四角实现寻找更好的逻辑与布局选择。功能RTL、时钟周期和外部模型保持。
3. `setup_optimization_goal_ns=0.3`：响应用户增加余量的要求，给原生优化器一个可调软目标；布线后额外执行一次原生全设计Setup优化。**0.3ns只是优化目标，不是验收门槛**；最终Setup/Hold仍按WNS≥0、TNS及违规路径0检查，不放宽20ns、3.8mm²或任何真实违规。

关闭自动门控、mux_dff以及全部复位/时序检查保持，防止重现历史ICG、E/SE最终复位违规。完整CPU、70个INT8计算单元、DMA/双tile和启动保护均保留。当前没有修改RTL；如果后续必须修改，将重新做适当的完整功能/复位回归并记录来源。

## 当前验证状态与后续

原生工具预检已完成：从TT库识别114种含负表项的组合单元；Genus初始化后对456个库角对象应用选择，小例实际网表不再包含被排除的单元。Innovus对114种物理主单元应用同一选择，Setup优化目标0.3ns读回约0.2999ns（工具精度）。同基线数据库还完成了16个负弧输入的真实边沿、负载、阈值和波形计算报告。原始开发日志仅本地archives，不进入分支。

第一轮a3c2141的完整SoC综合已实际得到68603个单元、2062766.560µm²单元面积（含SRAM401443.591µm²）；自动ICG、受控触发器及被排除组合单元实际实例均为0。候选32步Setup为+0.305ns、Hold显示+0.000ns，TNS及违反时序路径为0，Die仍为3.7956390976mm²。但原生电气检查发现一个真实的17>16扇出违规，环境退出0、EDA退出1，只有31步通过独立审核，因此**本轮实现未完成，也未运行新SDF后仿**。不能将这组候选数字当成完成后的改善，详见[失败依据](../eda/results/tt_setup_optimization_20261029/a3c2141_failure.json)。

违规网络原有16个功能负载，布线天线修复加入ANTENNABWP7T二极管后变为17。原生工具独立试验确认，即使设置fixFanoutLoad=true，postRoute阶段仍明确输出“Disabling fanout fix in postRoute stage”，追加一次原生DRV优化仍留下同一违规。因此不采用无效的后端重复修复，也不删二极管、改其模型或放宽原SDC的16。

后续修复使用`antenna_fanout_reserve=1`：原生布局/CTS/时序优化调用期间，将逻辑扇出目标设为15，为一个物理天线负载预留位置；29步布线前调用全设计`optDesign -postCTS -drv`，由原生工具选择缓冲结构。每次优化退出（包括错误）均恢复讲义的16，再独立生成检查报告、保存检查点及导出SDC。它是由实际二极管负载引出的实现预算，**不是新增验收条件**；最终天线与扇出16仍同时检查。脚本不指定网络或手工插接缓冲器。其面积、时序、天线和SDF影响必须通过新的干净上传、完整综合和34步验证。

独立、不保存数据库的原生试验已验证这个负载预算的作用：数据网络在15目标下无扇出残项；712个原有CTS输出仍为16，恢复讲义16后全设计扇出检查为0违规，未对时钟放宽限制。不过直接在旧布局中改树后，Setup降到−2.814ns、Hold降到−0.559ns，**这不是可交付实现**。新版本从布局/CTS开始使用该预算，并在29步对真实Setup/Hold残项有界重优化；只有重新完成四角静态、物理及三组SDF，才判定修复有效。开发试验的脚本和原始日志只保存在本地archives。
