## 面积分析方法

基线为main已验证的287ae40：含SRAM cell area=2067330.381µm²，64979个映射实例；含PAD Die=3.7956390976mm²，原生Density=74.633%，TT Setup/Hold=+0.350/+0.050ns。[绑定输入和基线](comparison_inputs.json)。

预期面积变化主要来自动态尺寸/续算控制、DMA可变块长度及地址计算，以及把现有FC1累加器接入MMIO的结果选择网络。输出总线不是额外的4096位寄存器。若总面积明显增长，应先看NPU top结果mux、核心控制及新增扇出缓冲，再决定是否值得收缩计算阵列。

编译器、PyTorch和CPU软件内核在电脑上或作为启动镜像运行，不作为新RTL综合进芯片。CPU fallback使用现有RV32IM处理器，其程序和LUT占8KiB SRAM容量，不自动增加物理SRAM面积。

必须分别报告cell area、标准逻辑/宏面积、各模块面积、原生逻辑密度和含PAD Die面积。固定Die保持相同不能解释为通用化面积零成本；含Filler占满率不能作为原生逻辑密度。没有同活动功耗分析时不声称功耗改善。

## 阵列缩小与5%周期门槛的下界

原四样本任务有4×(64×32+32×6)=8960次MAC。即使完全隐藏搬运、乘法器每拍全利用，8 MAC也至少需要1120个MAC发射周期；另有128个量化输出、2拍排空、20拍顺序Argmax，NPU下界约1270拍。原NPU实测952拍；若保持原程序配置及结果检查开销、CPU在NPU期间仅轮询，完整SoC下界约2700−952+1270=3018拍，超过允许的2835拍。

因此，对已承诺的四样本原用例，不能仅因单样本搬运受限就直接缩至8 MAC。12 MAC的理想下界约897拍，尚不能被该下界排除，但实际输出分组、尾部利用率、DMA等待和时序都需重新测量，不能据理想值承诺满足5%。当前保留16 MAC是有性能约束依据的选择；先优化外层约0.054606mm²新增逻辑，也比未经测量地缩阵列更有针对性。[下界计算输入](array_tradeoff_bound.json)。

进一步分解：NPU top组合面积增加0.052112mm²，Flop仅增加0.002033mm²；扣除core/weights后的外层组合增量0.050173mm²，占外层自身面积增量约91.9%。这支持优先分析结果读回选择与动态控制组合网络，而非把问题归到新增大存储阵列。
