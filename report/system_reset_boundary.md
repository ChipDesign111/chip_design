# 系统复位边界修复

be4a7fc已实测消除Wire Bond 9条，但TT后仿仍有两条最终复位违规。原输入SHA保持不变的被动探针复现了相同事件。

19.85ns复位相位中，ndmreset_n于238905.903ns下降，AXI r_ready于238910.355ns下降；仍处READ状态的桥随之重新拉高req，主存D于238911.655ns上升，仅领先CP238911.659ns 4ps，小于10ps。
2ns相位中，ndmreset_n于238888.053ns下降，上游AR地址随后异步清除，req_addr[31]的D于238891.678ns下降，仅落后CP238891.643ns 35ps，小于77ps。共享SRAM复位直到238921.873ns才下降。
因此问题是生产端先复位、接收端仍活动的窗口，不能当成普通同步短路径加延迟解决。

用户已明确允许把最多两个下降沿的复位识别延迟扩展到CPU/AXI/NPU系统时钟域，要求时钟运行，保留独立JTAG TAP复位。
新实现先对外部POR与NDM请求分别作两级下降沿采样；POR和功能复位同步器在下降沿释放。POR断言来自已采样的下降沿请求，NDM断言也来自同样边界。
功能ndmreset_n同时控制CPU、AXI、NPU和SRAM桥/命令寄存器，不再只给SRAM接收端增加两拍。JTAG TAP的trst_ni仍直接使用外部复位，NDM不清除独立POR/debug域。
已接受的SRAM载荷不异步清除，上一上升沿接受的操作在随后的下降沿完成一次；新请求在共同复位后停止。

44组数据用例和完整SoC通过；新增完整SoC复位契约测试覆盖80个POR相位和80个NDM相位，验证两下降沿内生效、共同边界、启动保护及独立debug域。
原生SRAM时序检查开启的16个原始完整SoC复位相位全部通过，原生产SDF激励未改。便携/原生两模型各80相位320场景均为642次接受=642次实际写。
首次功能回归的旧“1ns立即断言”断言按用户批准的两下降沿接口契约更新，未改SDF激励或关闭时序检查。
75项硬件来源SHA检查继续执行，SoC原始/上游SHA保留，当前改动在integration override中解释。[功能证据](functional_validation.json)单列当前RTL，旧物理结果不用于验证它。
