# SRAM复位RTL修正与main单TT基线

本文记录已合并main的5191064 RTL修正及其单TT实现。功能RTL未再变化；后续四角实现与三组SDF已完成，见[本轮最终结果](../eda/results/native_mux_dff_20261027/README.md)。下文“未做多PVT”对应本历史实现交付时点，不代表最新xzx状态。

## 要解决的问题

main 1192c32 的后仿记录中，正常工作窗口没有动态时序违规，但每组仿真结束重新复位时有一条 SRAM 地址建立时间违规：A[0] 比宏时钟上升沿早 122ps 变化，要求为 477ps。原接口将 AXI 的地址、请求和写信号直接接到宏；AXI 状态寄存器异步复位时，这些信号可能在不同物理延迟后改变。功能测试通过不能证明这种复位访问安全。

## 修改的文件及效果

| 文件 | 修改 | 原因与效果 |
| --- | --- | --- |
| rtl/memory/my_mainmem.sv | 系统上升沿接收命令并寄存 payload，SRAM 使用反相时钟 | 命令在随后的系统下降沿执行，读结果在下一上升沿响应采样前返回；保持原 AXI 周期关系 |
| 同上 | 地址、数据、字节写掩码不使用异步复位；请求有效位在系统上升沿受复位控制 | 上游异步清零不再直接传到宏引脚；已接受访问可以完成一次，复位期间后续请求被拒绝；不清空 SRAM |
| eda/server/postsim/tb_postsim.sv | 从宏实际时钟、CEN/WEN/A/D 观察完成标志 | 检查实际 SRAM 写入，而不是提前以 AXI 请求宣布成功 |
| eda/server/postsim/run.py | 16组 SDF 测试使用不同的最终复位相位 | 首组保留原2ns相位，其余15组从0.25ns到19.85ns覆盖一个20ns周期；时序检查和 notifier 保持启用 |

请求与 payload 的寄存器分开：payload 只在接受命令时变化，没有复位清零路径；请求有效位在时钟边沿撤销。复位不是“撤回所有已接受命令”，已经接收的写入仍可完成。系统时钟在复位期间需要继续运行，排空这一笔访问并停止后续访问。

不直接用异步 reset 与 SRAM 时钟做组合门控，也不把 reset 与宏 CEN 简单相与。这些做法会使时钟或使能在周期中途改变。

## 已完成的物理与SDF验证

反相 SRAM 时钟创建了真实的半周期路径：输入寄存器到宏，以及宏输出到 AXI 响应接收寄存器。必须重新综合、从新布局布线数据库导出 SDF，检查时钟相位、Setup/Hold、物理检查和最终复位事件；不能复用 e15483c 的 SDF 证明本次修改。

新实现从Genus及34步完整重跑，环境、EDA、整理均退出0。含PAD **3.7956390976mm²≤3.8mm²**，20ns下全局Setup/Hold **+0.371/+0.019ns**，所列最终物理检查通过。70个INT8乘法器、完整SoC、tile复用和DMA并行要求保持。[物理报告](../eda/results/sram_reset_20261027/README.md)保留同源34步及606份回传文件凭据。

只读加载同一step34数据库进行补充STA，输入寄存器→SRAM的Setup/Hold **+6.290/+10.194ns**，SRAM→接收寄存器 **+3.188/+11.476ns**。报告明确是0ns上升沿、10ns下降沿、下一20ns上升沿，sys_clk为传播时钟，没有把路径按全周期放宽。

由新数据库和原SDF运行16组完整SoC MAXIMUM SDF与1组独立无SDF功能对照，均完成CPU数值自检、DMA实际重叠和复位后禁止SRAM访问检查。16组SDF的初始化、工作、最终复位阶段均 **0条动态时序违规**；回标error、缺失实例和缺失检查均0。原来每组9条初始化+1条最终SRAM事件在本次实现中均未出现。首组保留2ns最终复位相位，其余15组覆盖0.25–19.85ns；所有时序消息和notifier始终开启。

部署源码提交5191064，独立物理上传为 `uploads/20261026_214621_5191064`；后仿为 `uploads/20261027_003144_postsim_bfc53d4`。冻结的服务器work输入未修改，原始仿真输入在补充STA后再次SHA复核一致。各目录README.html是服务器GUI入口。[后仿报告](../eda/results/sram_reset_20261027/postsim/README.md)包含全部74份轻量报告的归档与凭据。

本次仍有17条负IOPATH截零警告，以及每组时间0处的5条PAD模型BUS CONFLICT显示；原main也有这些PAD初始消息。后续时间没有该PAD消息，但这不证明PAD上电或ESD安全。负IOPATH属于模型/仿真器限制，未修改原SDF或关闭检查来消除告警。初始化事件的改善是本次完整实现的实测结果，不等于已经证明任意初态、任意PVT均安全。未做独立晶圆厂DRC/LVS、多PVT、IR/EM/ESD或形式等价。
