# SRAM 复位修正与验证状态

## 要解决的问题

main 1192c32 的后仿记录中，正常工作窗口没有动态时序违规，但每组仿真结束重新复位时有一条 SRAM 地址建立时间违规：A[0] 比宏时钟上升沿早 122ps 变化，要求为 477ps。原接口将 AXI 的地址、请求和写信号直接接到宏；AXI 状态寄存器异步复位时，这些信号可能在不同物理延迟后改变。功能测试通过不能证明这种复位访问安全。

## 修改的文件及效果

| 文件 | 修改 | 原因与效果 |
| --- | --- | --- |
| rtl/memory/my_mainmem.sv | 系统上升沿接收命令并寄存 payload，SRAM 使用反相时钟 | 命令在随后的系统下降沿执行，读结果在下一上升沿响应采样前返回；保持原 AXI 周期关系 |
| 同上 | 地址、数据、字节写掩码不使用异步复位；请求有效位在系统上升沿受复位控制 | 上游异步清零不再直接传到宏引脚；已接受访问可以完成一次，复位期间后续请求被拒绝；不清空 SRAM |
| eda/server/postsim/tb_postsim.sv | 从宏实际时钟、CEN/WEN/A/D 观察完成标志 | 检查实际 SRAM 写入，而不是提前以 AXI 请求宣布成功 |
| eda/server/postsim/run.py | 16组 SDF 测试使用不同的最终复位相位 | 首组保留原2ns相位，其余15组从0.25ns到19.85ns覆盖一个20ns周期；时序检查和 notifier 保持启用 |

请求与 payload 的寄存器分开：payload 只在接受命令时变化，没有复位清零路径；请求有效位在时钟边沿撤销。复位不是“撤回所有已接受命令”，已经接收的写入仍可完成。系统时钟在复位期间需要继续运行，排空这一笔访问并停止后续访问。

不直接用异步 reset 与 SRAM 时钟做组合门控，也不把 reset 与宏 CEN 简单相与。这些做法会使时钟或使能在周期中途改变。

## 仍需物理验证

反相 SRAM 时钟创建了真实的半周期路径：输入寄存器到宏，以及宏输出到 AXI 响应接收寄存器。必须重新综合、从新布局布线数据库导出 SDF，检查时钟相位、Setup/Hold、物理检查和最终复位事件；不能复用 e15483c 的 SDF 证明本次修改。

当前状态：RTL 功能回归已通过，新物理实现与 SDF 结果待完成。20ns周期、整颗含PAD≤3.8mm²、70个INT8乘法器与DMA并行要求保持。原有3.795639mm²/+0.226ns/+0.019ns属于旧RTL。

原后仿还有首个时钟附近的9条初始化事件，以及19条负IOPATH截零警告。前者需要用新SDF进一步区分启动模型瞬态与真实问题；后者属于当前模型/仿真器的回标行为。本次 SRAM 修改不能自动证明这两类问题消失，也不关闭检查来隐藏它们。
