# main 前端接入当前 RAW 后端的验证

已接入 main@4b552b1 的 PyTorch FX 前端，并为本分支的 RAW_INDEX/RAW_DATA/RAW_READY 实现部署后端。RTL、INT22 位宽、16-MAC、DMA 与现有版图签核流程均未修改，没有合并 main 的单层 FC／任务引擎接口。固定模型预打包和四项展开 CPU 内核复用现有实现。

## 同整数模型的实测

2026-11-18，Python 3.10.11、PyTorch 2.14.1+cpu、NumPy 2.2.6、ModelSim 2019.2。每个后端独立冷复位，真实 CPU 从 SRAM 执行；计时为实际 BEGIN/END 写入的接受边沿之差，包含初始化、调用、输入搬运、DMA、轮询、INT32 归约、CPU 激活及输出写回。测试完成后再由 Debug SBA 回读所有中间张量，逐值核对。

| PyTorch 图 | CPU 周期 | CPU＋RAW 周期 | 加速比 | RAW START 数 |
| --- | ---: | ---: | ---: | ---: |
| 64→32 Linear | 36953 | 3926 | 9.412× | 1 |
| 65→33 Linear，两个边缘 | 38499 | 7792 | 4.941× | 1 |
| 混合 65→33→5，Sigmoid／残差／Softmax | 56317 | 16334 | 3.448× | 1 |
| 同一混合图，留出输入 | 56316 | 16332 | 3.448× | 1 |
| 64→32，batch=2 | 66621 | 7025 | 9.483× | 2 |
| 整层累加范围超 INT22 的 64→32 | 33567 | 4002 | 8.388× | 1 |
| 小型 17→9→5→3 | 5684 | 5684 | 1.000× | 0 |
| 纯 CPU 算术、激活和 Softmax，batch=2 | 5062 | 5062 | 1.000× | 0 |
| 原地 ReLU 图 | 86 | 86 | 1.000× | 0 |

加速比为同一图、同一权重／输入／量化规则下 `CPU 周期 / CPU＋RAW 周期`。没有完整块时两个路径生成同一 CPU 程序，不将 1.000× 计作 NPU 加速。新图使用逐层有符号 INT8 边界和新的代码／数据布局，因此不把这些数值直接套到旧整数模型。

补充的大矩阵使用相同后端，权重仍只保存一份，全部数据和程序在 8 KiB SRAM 内：

| 输出×输入 | CPU 周期 | CPU＋RAW 周期 | 加速比 | RAW START 数 |
| --- | ---: | ---: | ---: | ---: |
| 64×64，跨两个输出块 | 67039 | 7602 | 8.819× | 2 |
| 33×129，跨输入块并含边缘 | 66326 | 10510 | 6.311× | 2 |

前者固定 seed=181128，后者 seed=181129，使用 `nn.Linear(K,N).eval()` 和 `torch.linspace(-1,1,K).reshape(1,K)`，校准为 `[-x,x*0.5]`。分别验证输出偏移、多次输入块归约，以及最后一列／最后一行 CPU 计算。CPU 与 RAW 的逐层整数参考一致，全部实际 SRAM 输出一致。

## 原功能保持

`compile_layers` 是原整数模型的部署包装，保留原来的 ReLU、软件64位重定标和末层 INT32 分数。七个既有模型、两个后端共14份计时镜像，与原记录逐字节相同。代表模型还重新跑了四次完整 SoC：

| 旧整数模型 | CPU 周期 | 优化 RAW 周期 | 与旧记录 |
| --- | ---: | ---: | --- |
| 32×64 | 45624 | 4997 | 全部一致，9.130× |
| 33×65 | 47397 | 9199 | 全部一致，5.152× |

原 HAR 仍为 `cycles=2700 / hw_soc_cycles=2695`，DMA 读／写／总 overlap 为 `466 / 499 / 500`。41组原计算、8组 DMA、Boot 周期及80 POR/80 NDM复位契约通过。RAW32组、2560个结果及故障、流水撤销和模式切换回归通过。

## 接入方式与检查

- `frontend.py` 与 main@4b552b1 逐字节一致，SHA-256 为 `84bcf3955f7addc9cd6ebcd49bc6e7c4b11a8141c126a37da300963f8e6425b7`。八种图在同一环境下，与 main 的独立 CPU 整数参考逐张量相同。
- 在调用前端时复制示例及校准张量，修复原地 ReLU 导致调用者输入被修改的副作用；前端源码本身保持一致。10项主机契约检查通过，已加入独立 CI 任务。
- 图 Linear 使用共享的 CPU 四项展开子程序；完整块调用现有 `_full_blocks`，边缘使用现有 `_cpu_kernel`。NPU bias1 清零，真实 bias 与跨块归约留在 CPU，允许整层超过 INT22、仍能证明 INT32 安全的模型。
- 其余已注册算子由 CPU 内核执行。保留 main 的逐层有符号 INT8 舍入边界，不把 Linear→ReLU 擅自融合为不同整数语义。未注册算子、动态形状、广播、超容量或无法证明安全的算术明确拒绝。
- 图部署包没有嵌入 golden 输出；testbench 检查 END 前的所有输出写入，结束后再 SBA 回读。整数兼容镜像保留旧自检，golden 只在 END 后访问。CLI 模型工厂编译结果与同模型 API 的机器码 SHA 一致；更换留出输入保持机器码不变。
- 所有加载的 HEX 与 BIN 都逐字节核对，源码、固件、reference、实际输出、生成 testbench 和日志 SHA 见 [验证记录](raw_frontend_validation.json)。图程序不提供软件阶段的逐拍归因，使用总周期及 NPU 硬件计数；保留的阶段栏不能解释为图阶段耗时。

主套件22次 SoC 和补充4次 SoC 全部通过。浮点误差与整数实现误差分开记录：主套件各图的最终浮点最大绝对误差约为0～0.0071，不作为实际任务准确率结论。功能仿真为10ns时钟，没有为新 PyTorch payload 重做 ASIC SDF 或 FPGA 板测，不扩大已有物理结果的验证范围。

使用说明见 [compiler](../compiler/README.md)，演示模型见 [raw_mixed](../model/raw_mixed/README.md)。主证据为本地忽略的 `test/int8/runs/raw_frontend_20261118_164618/`，补充矩阵为 `raw_frontend_large_20261118_165335/`；修复输入副作用之前的初轮运行明确标记中断，不计入验收。
