# RAW 跨样本权重复用

当前编译器默认让 batch=2..4 共用一次完整权重块 DMA，采用原硬件已有的多样本 RAW 能力。main@4b552b1 的前端保持原样；本次仅修改编译后端、测试与文档。

## 实测结果

2026-11-18，完整 CV32E40P / AXI / DMA / 8 KiB SRAM SoC。满块为 `64→32 Linear`，使用 `raw_batch_cases.py` 固定随机权重和各不相同的样本行；三个路径的量化模型与输入相同。CPU 仍为原四项展开标量内核。

| batch | 纯 CPU | 原逐样本 RAW | 新 RAW | 原 RAW / 新 RAW | CPU / 新 RAW |
|---:|---:|---:|---:|---:|---:|
| 1 | 36,953 | 3,926 | 3,926 | 1.000× | 9.412× |
| 2 | 77,684 | 7,912 | 6,737 | 1.174× | 11.531× |
| 3 | 116,224 | 11,469 | 9,530 | 1.203× | 12.196× |
| 4 | 180,188 | 15,919 | **12,311** | **1.293×** | **14.636×** |

四样本满块周期减少 **22.66%**，RAW 启动由 4 次降为 1 次，权重 DMA 描述符由 128 个降为 32 个，权重流量由 8192 B 降为 2048 B。MAC 发射总数仍为 512，结果仍需读取 128 个。更换留出输入后机器码不变，四样本周期仍为 15,919 / 12,311。

不同 batch 的生成程序布局不同，CPU 拍数不能按样本数线性外推。表中的提升是相对固定旧内核/旧调度的实测，不是 CPU 峰值能力，也不能直接与另一模型的 HAR 加速比比较。

| 场景（输出×输入） | batch | 原逐样本 RAW | 新 RAW | 原 RAW / 新 RAW | 启动数变化 |
|---|---:|---:|---:|---:|---:|
| 32×128，跨输入块 | 4 | 22,702 | 19,218 | 1.181× | 8→2 |
| 64×64，跨输出块 | 3 | 21,967 | 18,694 | 1.175× | 6→2 |
| 33×65，右边缘与底部 | 4 | 28,120 | 26,323 | 1.068× | 4→1 |
| 32×65，仅右边缘 | 3 | 19,384 | 16,343 | 1.186× | 3→1 |
| 33×64，仅底部 | 2 | 9,463 | 9,155 | 1.034× | 2→1 |
| 64→32→64，多层与 ReLU/Tanh | 2 | 91,985 | 83,457 | 1.102× | 2→1 |
| 32×128，整层累加范围超 INT22 | 3 | 17,542 | 14,909 | 1.177× | 6→2 |
| 32×64，零位移重定标 | 2 | 7,440 | 6,737 | 1.104× | 2→1 |
| 32×176，容量回退 | 4 | 136,835 | 136,835 | 1.000× | 8→8 |
| 17→9→5，CPU-only | 4 | 21,017 | 21,017 | 1.000× | 0→0 |

原前端接入报告里的 `batch2` 模型也重新运行：CPU 仍为 **66,621** 拍，RAW 从原 **7,025** 拍降为 **6,737** 拍，对同整数 CPU 的加速比约 **9.889×**。它与上表 `full_b2` 的权重及程序布局不同。

本次测试覆盖 16 组输入配置（含两个留出输入），最终表格绑定 34 份不同固件的完整 SoC 执行记录，其中启用权重复用的 13 份均已用最终对齐版本复测。全部图张量在 END 前检查、结束后由 SBA 实际读回。零位移的留出输入同时覆盖 -128 / 127 饱和边界。

## 调度和数值

原调度逐样本计算完整矩阵，每个样本都会重新搬运公共权重。新调度在每个 32 输出块内，先给所有样本初始化偏置，再遍历 64 输入块：

1. CPU 将每个样本当前的 64 维输入写入各自 NPU 窗口，设置硬件 batch。
2. 一次 RAW 启动加载 2048 B 公共权重，NPU 在释放每个 tile 前服务全部样本。
3. CPU 按 `sample×32+output` 读取有符号 INT22 部分和，分别加到 INT32 `[batch,32]` 累加区。
4. 遍历完全部输入块后，用原四项展开 CPU 点积计算右边缘，再执行相同的 signed INT8 重定标并写回各样本输出。
5. 下一个输出块复用同一累加区；最后不足 32 行的底部由 CPU 逐样本计算。返回前恢复硬件 batch=1。

多样本 RAW 的临时空间为 `batch×32×4` B，最大 512 B；它与其他 CPU 层的累加区共用，若其他 CPU 层需要更大空间则按最大需求分配。权重仍保持紧凑预排，只保存一份。跨输入块始终在 CPU 中作 INT32 累加，不引入 INT22 整层回绕，也不提前重定标。

每个矩阵层的 RAW 任务数由 `B×floor(N/32)×floor(K/64)` 降为 `floor(N/32)×floor(K/64)`。权重 DMA 流量按 batch 倍减少；MAC 工作量和逐样本结果数量不变，所以端到端加速需要实测。

新路径还将原四项展开 CPU 点积的 80 B 热循环对齐到 16 B，从跨六条取指行缩至五条。操作和展开度不变，原逐样本/纯 CPU 程序不加对齐指令；这能减少新函数布局对 CPU 边缘和后续 CPU 层的影响。最终周期包含此对齐。

## 容量与兼容

新调度增加的代码和缓冲仍受同一块 8 KiB SRAM 限制。遇到容量不足，编译器使用原校准图重试逐样本调度，保留原先能部署的模型。其他编译错误仍正常报告。manifest 会记录 `batch_weight_reuse_fallback`，不会将回退误报为已优化。

可通过 API `compile_model(..., reuse_batch_weights=False)` 或 CLI `--no-batch-reuse` 显式使用原调度。batch=1、纯 CPU、无完整块的模型及原整数 `compile_layers` 保留原代码路径。

容量案例 `32×176、batch=4` 在原调度下剩余 104 B；新调度放不下时，自动回退得到相同固件和周期，没有拒绝这个原先可部署的模型。

14 项主机契约测试通过，包括 14 份历史整数固件 HEX 保持检查。显式关闭复用后，本轮预先冻结的 40 份 CPU/逐样本 RAW 固件与修改前逐字节一致；其中 30 份在默认设置下也保持一致。CPU/原 RAW 的执行记录经过最终编译器重新生成镜像并核对全部字节，因此仍作为有效的最终基准。对齐前的中间版本结果不用于上表新 RAW 列。

原硬件 RAW 回归的 32 组、2560 个结果和故障/模式切换全部通过；原 HAR 的 41 组计算、8 组 DMA 响应以及 80 POR / 80 NDM 复位契约通过。HAR 完整 SoC 仍为 2700 / 2695 拍，NPU 为 952 拍，DMA read/write/total overlap 仍为 466 / 499 / 500。

源码、执行镜像、最终重编译包、实际输出、testbench 和日志哈希见 [验证记录](raw_batch_reuse.json)。

## 复现

安装 [编译器依赖](../compiler/requirements.txt)，然后运行：

```bash
python test/int8/test_raw_compiler.py
python test/int8/run_raw_batch_reuse.py --soc --vsim /path/to/vsim
python test/int8/run_raw_batch_reuse.py --soc --case full_b4 --backend cpu --backend sequential --backend reuse --vsim /path/to/vsim
```

默认比较 sequential/reuse，可用 `--case` 限定模型。输出在本地忽略的 `test/int8/runs/raw_batch_<时间戳>`。所有路径使用同一量化规则和参考，真实 CPU/AXI/DMA/NPU 执行后由 SBA 回读全部图张量；计时仍为 SRAM 接受 BEGIN/END 的区间，包含配置、输入、DMA、轮询、CPU 归约/边缘/激活和结果写回。

相同固件镜像只进行一次 SoC 仿真，结果用 `same_firmware_as` 标明；这类复用不计为新增仿真。功能时钟为 10 ns。

## 文件

- [batch_codegen.py](../compiler/batch_codegen.py)：输出块调度、批量输入/结果读回、CPU 边缘和动态重定标。
- [compiler.py](../compiler/compiler.py)：批处理描述符、共享累加区、任务计数和容量回退。
- [codegen.py](../compiler/codegen.py)：选择多样本/原单样本路径并共享原 CPU 内核。
- [rv32.py](../compiler/rv32.py)：为指定热循环标签插入对齐 NOP，其他标签仍沿用原行为。
- [tb_gemv_benchmark.sv](../test/int8/tb_gemv_benchmark.sv)：增加预期硬件 batch 检查，核对每次 RAW 发射数，默认 batch=1 保持其他入口兼容。
- [raw_batch_cases.py](../test/int8/raw_batch_cases.py)、[run_raw_batch_reuse.py](../test/int8/run_raw_batch_reuse.py)：固定模型和输入的逐样本/复用对照，另支持纯 CPU。
