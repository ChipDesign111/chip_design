# 详细项目计划

版本：2026-10-08；适用于 ChipDesign111/chip_design。先安排共同工作和验收，不分配四人个人职责。

## 1. 最终目标与边界

在共同选定的课程 RISC-V SoC 底座上，设计人体活动识别 NPU。输入是已预处理的 64 维 INT8 特征；网络为 64→32→6，两层矩阵向量乘、偏置、第一层 ReLU/量化、最终 Argmax。

首版预处理在主机完成，不默认开发传感器板或把原始信号特征提取硬件化。最终成果包括：模型与整数参考、RTL 与驱动、仿真与 FPGA 证据、ASIC 签核与 GDS、报告及 AI 记录。

参数 2,278，每次推理 2,240 次乘加。模型识别准确率与硬件计算正确性分别评估：整数硬件须与整数参考逐项一致，真实数据识别准确率单独统计。

## 3. 阶段 A：组织与共有工程

本次完成选择性导入、共享入口和本机平台回归。无需等待真实模型才开发 RTL；模型缺席时使用合成权重验证，后续优先对接真实数据及模型，然后评估 NPU 存储/综合。现有 16 周学习安排保留为参考，并非当前进度要从第 1 周重新开始。

任务：
1. 四人使用个人账号加入组织；仓库权限按团队配置，不共享登录凭据。
2. 克隆共有仓库，各用独立本机和 CLab 工作目录。
3. 评审目录边界、PR 规范、任务模板和忽略规则。
4. 从正式发布包选择官方基础代码，确认允许上传的范围，保留来源、版本与许可证。
5. 建立 filelist 和运行入口，记录仿真器、RISC-V 工具链与 Python 版本。
6. 导入后运行原模板自检；必要个人实现以独立 PR 贡献。
7. 在第二个独立目录复现，通过后标记共有平台基线。

交付：来源清单、环境文档、干净可复现的基础工程、验证摘要。
验收：课程基础测试满足对应要求，另一环境照文档可复现。
标签：骨架用 v0.0-scaffold；真正验证后用 v0.1-shared-platform。

## 4. 阶段 B：资料、算法与规格

必须确认：真实数据是否提供、64 个特征的含义与顺序、是否有权重、类别编号、量化参数、准确率要求、目标频率、存储资源、FPGA 板卡及 I/O 约束。

算法步骤：
1. 如有提供模型，复现；否则训练固定 64→32→6 MLP。
2. 数据划分避免受试者和相邻采样泄漏；归一化参数用训练集拟合。
3. 输出浮点准确率、各类表现、混淆矩阵。
4. 建立整数模型，检查精度损失，导出权重、偏置、量化参数。
5. 保存每条样本的输入、32 个中间激活、六个得分及类别。
6. 评审并冻结 spec、numerics、mmio，记录版本。

交付：模型版本、数据处理方法、参考程序、权重和测试向量。
验收：可重复生成相同输出；数值规则足以直接实现 RTL。
资料未齐时可用合成数据开发算子；合成测试不构成活动识别准确率证明。

## 5. 阶段 C：NPU RTL

按顺序：
1. 有符号乘法、累加、偏置。
2. 舍入、饱和、ReLU 与 Argmax 单元。
3. 第一层 64→32，逐项比较中间结果。
4. 第二层 32→6，比较六个得分。
5. 两层状态控制，复位、连续启动、完成状态。
6. 数据存储和 MMIO 装载。
7. 完整固定向量与随机回归。
8. 早期试综合，确认存储映射、面积和关键路径。

V1 先用一个 MAC；在正确版本上评估是否增加并行度。不为追求理论周期改变尚未冻结的数值规则。
交付：RTL、独立测试、失败样例和回归报告。
验收：中间值、得分、类别与整数参考一致；无未知值影响结果。
标签：v0.2-har-npu。

## 6. 阶段 D：软件与 SoC

1. 建立裸机 RISC-V 构建链：C/汇编→ELF→map/反汇编→hex。
2. 验证一个简单程序可在共同平台运行，明确启动和镜像排列。
3. 驱动采用 32 位 MMIO；权重可初始化装载一次，多样本复用。
4. CPU 先写输入，再启动，带超时轮询，读回得分与类别。
5. 核查 8 KB SRAM 中代码、权重、输入、参考输出、栈和测试标志区是否冲突。
6. 编写自主 SoC testbench，保留官方测试不修改。
7. 运行真实 CPU 端到端测试；比较软件参考和硬件结果。
8. 测量 CPU 单独推理、NPU 核心、含传输端到端周期，分别说明首次权重装载。

交付：可复现软件构建、驱动、镜像、SoC 测试。
验收：真实 CPU 能完成多次推理，结果逐项一致，超时可诊断。
标签：v0.3-har-soc。

## 7. 阶段 E：FPGA

待 Lab 6 发布后确认板卡、存储、时钟、引脚和调试入口。
步骤：存储适配→时钟复位→引脚/时序约束→综合实现→bitstream→JTAG/OpenOCD/GDB 调试→运行软件→对比参考。
功能展示包含真实样本、类别与得分、连续推理和耗时。保存板卡、工具、模型与代码版本。
验收：上板结果正确，可重复演示。FPGA 不代替 ASIC 时序和物理签核。
标签：v0.4-har-fpga。

## 8. 阶段 F：ASIC 与交付

模板 Lab 4/5 学习提前完成；自主 RTL 开发期做试综合。
正式流程：约束→综合→Floorplan/Powerplan→Placement→CTS→Routing→签核→GDS。
检查：不期望的锁存器、存储实现、未约束路径、面积含 CPU/存储/I/O、布线拥塞、时序和物理违规。
优化修改 RTL 后必须重跑受影响回归，并记录与报告一致的 commit。
课程讲义目标：约 2×2 mm（含 I/O），满足时序及 DRC/LVS/Antenna Clean；最终以课程正式约束为准。
功耗结果说明活动数据、分析阶段和条件；无工具结果时不填估计值冒充实测。
交付：最终代码、模型、软件、约束、测试摘要、签核材料、GDS 清单和校验值。
验收：评审问题关闭、签核通过、所有材料版本一致。
标签：v1.0-tapeout。回片、封装测试归下学期安排。

## 11. 每周共同验收

每周开始确认任务、依赖和验收；周中遇到接口问题立即记录；周末运行对应共同版本并填写 weekly 模板。
看板列：待开始→进行中→待验证→完成。每项 Issue 有范围、依赖、验收命令和证据，不在此阶段固定个人分工。

## 12. 风险与处理

| 风险 | 提前处理 |
| --- | --- |
| 数据/权重迟到 | 开始阶段确认来源；合成数据仅用于开发测试 |
| 量化规则不一致 | 先冻结 numerics，再写 RTL 与驱动 |
| SRAM 超限 | INT8 保存权重、一次少量样本、检查 map 和栈 |
| 存储被实现成大量触发器 | 早期试综合，按课程可用宏调整 |
| 接口读延迟/地址错 | 独立 MMIO 测试，明确 word/byte 和打包 |
| 优化占用交付时间 | 保留通过验证的 V1，优化以证据决定 |
| 课程要求更新 | 更新来源、决策和计划；重评受影响规格 |
| 无法复现 | 环境配置外置、脚本定位根目录、记录版本 |
