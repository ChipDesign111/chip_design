# Release process

## 版本和状态

正式版本标签采用 vMAJOR.MINOR.PATCH。寄存器、算术或软件兼容性破坏需要明确迁移说明；非破坏性能力增加和修复分别更新对应版本段。未建立正式标签的当前开发状态记录在 CHANGELOG 的 Unreleased。

功能仿真、FPGA 验证与 ASIC 签核是不同交付状态。版本说明必须标注所达到的层级，不以标签名称代替证据。

## 候选检查

1. 固定源 revision、模型版本与输入校验值；工作树无未记录修改。
2. 运行 `python project.py ci`，检查公开 CI 全部成功。
3. 运行适用的本地 soc / model-soc；数值、RTL 或固件变化包含完整真实数据回归。
4. 核对 90 文件平台完整性、组件声明、构建产物范围和已知限制。
5. 将报告记录到 reports，说明工具版本、命令、测试数量、结果与覆盖范围。
6. 目标实现交付增加目标综合/约束/STA/板级或物理签核证据。
7. 审阅候选，建立版本标签和发布说明，归档允许分发的证据。

GitHub 仓库规则建议保护 main、要求适用的 CI 与审阅、避免强制改写；实际服务器设置由维护者管理，本工程文档不将建议写成已启用状态。

## 发布清单

| 对象 | 记录 |
| --- | --- |
| 源码 | revision、配置、接口版本、组件来源 |
| 模型 | 权重/偏置/量化/特征/标签及 SHA |
| 程序与向量 | 生成命令、SHA、SRAM 用量 |
| 仿真 | 套件、数量、结果、工具与限制 |
| 目标实现 | 约束、映射、时序、资源、板级/物理检查 |
| 分发范围 | 组件许可证、数据引用、排除的受限内容 |

不将 PDK、标准单元库、许可证、凭据或未审查的本地数据库加入发布包。历史基线和生成产物的边界见 [reports](../reports/README.md)。
